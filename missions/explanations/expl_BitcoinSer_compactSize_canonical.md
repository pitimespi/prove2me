We prove that a successful read determines the input. `readCompactSize` on `ch :: tl` dispatches on `ch`. Below $253$: the value is `ch`, the remainder `tl`, and `writeCompactSize ch = [ch]` since `ch < 253` (`BitVec.ofNat_toNat`). For a marker $253/254/255$: the inner `readLE` succeeded on `tl` with some value $v$ and remainder $r$, and `readLE_inv` shows `tl = leBytes k v ++ r` with $v < 2^{8k}$ — the bytes read are the encoding of the value read (`leBytes_leVal`: encoding the little-endian value of a $k$-byte list gives the list back). The non-canonical test that passed gives $v \ge 253$, $\ge 2^{16}$ or $\ge 2^{32}$, which together with the width bound selects exactly the same branch of `writeCompactSize`, so `writeCompactSize v ++ r = ch :: leBytes k v ++ r = ch :: tl`. The shared tail argument is `tail_inv`; the top-level theorem is a projection of `compactSize_inv`, which also carries the range facts.
