The private lemmas `spec_commit` and `markCommitted_spec` give that the commit is for the current term and the accepted key, and that only the last committed configuration changes, to the last accepted one. The accepted key is therefore committed (`hcomm`), of term at least 1, and for an eligible node it is a publication with the node's last accepted configuration (`hQ`). A node that has not won holds no quorum of its last accepted configuration (`hnoq`: the publisher of its accepted publication has voters forming a quorum of that configuration, `pub_voters`; a common voter and `join_unique` make the node that publisher, contradicting `pub_source_term` and `votes_started`). The fields: `won_quorum` because both configurations are now the last accepted one; `not_won_no_quorum` by `hnoq`; `accepted_realizes` by the committed case of `Realizes`; `leader_inflight` in the D1 case of a leader with a publication `C` in flight: `pub_parent` (R2) for `C` gives either the same last accepted configuration as the parent, which is the D1 disjunct, or a last committed configuration equal to the parent's last accepted one, which is the node's new one; `leader_settled` because the commit's term is the current term; everything else is unchanged.
