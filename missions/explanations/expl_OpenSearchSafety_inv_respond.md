The private lemma `spec_respond` gives that the node has won, that the response is for its current term and last published version, that only the publish votes change, and that a returned commit is for (current term, last published version) with the new votes a quorum of the last committed and last published configurations. The new votes are responses to that key from eligible nodes (`hA`, from `publishVotes_sent` and the handled response). The commit-quorum record for a new commit (`hC1`): `response_published` gives the publication `C` in flight; by `leader_settled` and `accepted_realizes`, or by `leader_inflight` (with `pub_unique`), the last published configuration is `C`'s last accepted configuration and the last committed configuration is `C`'s, or (D1) `C`'s last accepted one with the parent committed and of the same last accepted configuration, or `C`'s key is already committed, in which case the earlier commit's record serves. A `suffices` over any cluster with the new node state and the old messages, plus the commit if any, treats both outcomes at once; the remaining fields carry over by monotonicity.
