`readLE k s` fails only if $|s| < k$ and otherwise returns `(leVal (s.take k), s.drop k)`. With $s = \mathrm{leBytes}(k,n) ++ r$ the prefix has length $k$ (`leBytes_length`), so `take`/`drop` split it at the boundary (`List.take_left'`, `List.drop_left'`). It remains that $\mathrm{leVal}(\mathrm{leBytes}(k,n)) = n$ for $n < 2^{8k}$: by induction on $k$, $\mathrm{leVal}$ of the encoding is $(n \bmod 256) + 256 \cdot \mathrm{leVal}(\mathrm{leBytes}(k, n/256))$, and $n/256 < 2^{8k}$ follows from $n < 2^{8(k+1)} = 2^{8k} \cdot 256$, so the hypothesis gives $(n \bmod 256) + 256 (n / 256) = n$.
