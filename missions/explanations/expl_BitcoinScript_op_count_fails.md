We prove that a script with more than 201 counted opcodes never evaluates successfully. `opsIn` counts exactly what `nOpCount` counts: non-push opcodes above `OP_16`.

Two step facts. `step_push_opCount`: a successful push step leaves `opCount` unchanged (the pushed state is `{ s with stack := … }` or `s`). `step_op_opCount`: a successful opcode step satisfies $s.\mathrm{opCount} + [\,\mathtt{OP\_16} < c\,] \le s'.\mathrm{opCount}$, and $s'.\mathrm{opCount}$ is either $s.\mathrm{opCount}$ or at most $201$. For a counted opcode the step fails unless $s.\mathrm{opCount} + 1 \le 201$ and then sets the count to $s.\mathrm{opCount} + 1$; an uncounted one leaves it; in both cases the opcode is then skipped (count unchanged) or executed, and by `BitcoinScript.execOp_opCount` execution leaves the count unchanged or within the limit.

The loop invariant `run_opCount`: if `run f o s script = some s'` then $s.\mathrm{opCount} + \mathrm{opsIn}(script) \le s'.\mathrm{opCount}$, and $s'.\mathrm{opCount} = s.\mathrm{opCount}$ or $s'.\mathrm{opCount} \le 201$. By induction on the script, combining the step fact for the head with the induction hypothesis for the tail; the disjunction composes because "unchanged" is transitive and "within the limit" propagates.

Applied to `State.initial stack` (count $0$) with $\mathrm{opsIn}(script) > 201$: a successful run would give $s'.\mathrm{opCount} \ge \mathrm{opsIn} > 201$, so the count is neither $0$ nor $\le 201$, a contradiction; hence `run` returns `none` and so does `evalScript`.
