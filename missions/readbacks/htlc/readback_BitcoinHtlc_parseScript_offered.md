# Read-back: `BitcoinHtlc.parseScript_offered`

**Statement.** Let $r, K_r, K_l, h$ be any four byte strings with $|r| \le 520$, $|K_r| \le 520$, $|K_l| \le 520$, $|h| \le 520$. The theorem asserts

$$\mathrm{parse}\bigl(\mathrm{OffB}(r, K_r, K_l, h)\bigr) = \mathrm{some}\bigl(\mathrm{Off}(r, K_r, K_l, h)\bigr),$$

i.e. the byte-level parser applied to the serialized offered-HTLC byte string returns (without failure) exactly the 26-instruction list $\mathrm{Off}(r, K_r, K_l, h)$; both sides are unfolded below. Equality is equality of optional instruction lists, where an instruction is either a data push carrying a byte string or a non-push opcode byte.

---

## Definitions unfolded

**Basic notions used throughout.** A *byte* is an 8-bit word and a *byte string* (written $\mathrm{Bytes}$) is a finite list of bytes; $|b|$ denotes the length of a byte string $b$. The constant $L_{\max} = 520$ is the interpreter's maximum size of one stack element. A *flag set* $f$ consists of three Booleans $f.\mathrm{cltv}$, $f.\mathrm{csv}$, $f.\mathrm{nulldummy}$. An *oracle* $o$ is an arbitrary structure supplying eight functions with no constraints whatsoever on their behaviour: $o.\mathrm{ripemd160}, o.\mathrm{sha1}, o.\mathrm{sha256}, o.\mathrm{hash160}, o.\mathrm{hash256} : \mathrm{Bytes}\to\mathrm{Bytes}$ (so in particular $o.\mathrm{hash160}$ is *any* function from byte strings to byte strings, not necessarily RIPEMD160$\circ$SHA256, not necessarily 20-byte-valued), $o.\mathrm{checkSig} : \mathrm{Bytes}\to\mathrm{Bytes}\to \mathrm{Option}\,\mathrm{Bool}$ (first argument the signature, second the public key; the value $\mathrm{none}$ represents a script-aborting failure, $\mathrm{some}\,b$ a verdict $b$), $o.\mathrm{checkLockTime} : \mathbb{Z}\to\mathrm{Bool}$ and $o.\mathrm{checkSequence} : \mathbb{Z}\to\mathrm{Bool}$. Stacks are lists written top element first. $\mathrm{castToBool}(b)$ is: false for the empty string; for a one-byte string $[x]$, true iff $x\neq 0$ and $x \neq 0\mathrm{x}80$; for $x :: r$ with $r$ non-empty, true iff $x\neq 0$ or $\mathrm{castToBool}(r)$ (so a string of zero bytes whose last byte is $0\mathrm{x}80$ is false). $\mathrm{boolBytes}(\mathrm{true}) = [0\mathrm{x}01]$ and $\mathrm{boolBytes}(\mathrm{false}) = []$ (the empty string). The script-number encoding $\mathrm{ser}(v)$ of an integer $v$ is: $[]$ if $v = 0$; otherwise the little-endian bytes of $|v|$ with no trailing zero byte, then, if the last of those bytes has its top bit ($0\mathrm{x}80$) set, an extra byte $0\mathrm{x}80$ (for $v<0$) or $0\mathrm{x}00$ (for $v>0$) is appended, and otherwise, for $v<0$, the top bit of the last byte is set. For example $\mathrm{ser}(2) = [0\mathrm{x}02]$ and $\mathrm{ser}(32) = [0\mathrm{x}20]$. The decoding $\mathrm{num}_k(b)$ ("script number of at most $k$ bytes, non-minimal encodings allowed") is $\mathrm{none}$ if $|b| > k$, and otherwise $\mathrm{some}$ of the little-endian value of $b$ with the top bit of the last byte read as a sign (the empty string decodes to $0$).

**The number push $\mathrm{numInstr}(n)$ / $\mathrm{numBytes}(n)$.** For an integer $n$, $\mathrm{numInstr}(n)$ is the single opcode with byte value $n + 0\mathrm{x}50$ when $n = -1$ or $1 \le n \le 16$ (so $\mathrm{numInstr}(-1)$ is the opcode $0\mathrm{x}4\mathrm{f}$, $\mathrm{numInstr}(2)$ is the opcode $0\mathrm{x}52$, i.e. `OP_2`), and otherwise it is the data push of $\mathrm{ser}(n)$ (so $\mathrm{numInstr}(32)$ is the push of the one-byte string $[0\mathrm{x}20]$, and $\mathrm{numInstr}(0)$ is the push of the empty string). $\mathrm{numBytes}(n)$ is the byte-level form: the one opcode byte $n + 0\mathrm{x}50$ in the first case, and $\mathrm{pushBytes}(\mathrm{ser}(n))$ otherwise, where $\mathrm{pushBytes}(d)$ is the canonical push encoding of a byte string $d$: $[\,|d|\,] \mathbin{+\!\!+} d$ if $|d| < 0\mathrm{x}4\mathrm{c}$; $[0\mathrm{x}4\mathrm{c}, |d|] \mathbin{+\!\!+} d$ if $|d| \le 0\mathrm{xff}$; $[0\mathrm{x}4\mathrm{d}] \mathbin{+\!\!+} (\text{2 little-endian bytes of } |d|) \mathbin{+\!\!+} d$ if $|d| \le 0\mathrm{xffff}$; and $[0\mathrm{x}4\mathrm{e}] \mathbin{+\!\!+} (\text{4 little-endian bytes of } |d|) \mathbin{+\!\!+} d$ otherwise.

**The two witness scripts as byte strings.** $\mathrm{OffB}(r, K_r, K_l, h)$ is the byte string

$$[0\mathrm{x}76, 0\mathrm{xa}9] \mathbin{+\!\!+} \mathrm{pushBytes}(r) \mathbin{+\!\!+} [0\mathrm{x}87, 0\mathrm{x}63, 0\mathrm{xac}, 0\mathrm{x}67] \mathbin{+\!\!+} \mathrm{pushBytes}(K_r) \mathbin{+\!\!+} [0\mathrm{x}7\mathrm{c}, 0\mathrm{x}82] \mathbin{+\!\!+} \mathrm{numBytes}(32) \mathbin{+\!\!+} [0\mathrm{x}87, 0\mathrm{x}64, 0\mathrm{x}75] \mathbin{+\!\!+} \mathrm{numBytes}(2) \mathbin{+\!\!+} [0\mathrm{x}7\mathrm{c}] \mathbin{+\!\!+} \mathrm{pushBytes}(K_l) \mathbin{+\!\!+} \mathrm{numBytes}(2) \mathbin{+\!\!+} [0\mathrm{xae}, 0\mathrm{x}67, 0\mathrm{xa}9] \mathbin{+\!\!+} \mathrm{pushBytes}(h) \mathbin{+\!\!+} [0\mathrm{x}88, 0\mathrm{xac}, 0\mathrm{x}68, 0\mathrm{x}68]$$

(the opcode bytes are `OP_DUP OP_HASH160 … OP_EQUAL OP_IF OP_CHECKSIG OP_ELSE … OP_SWAP OP_SIZE … OP_EQUAL OP_NOTIF OP_DROP … OP_SWAP … OP_CHECKMULTISIG OP_ELSE OP_HASH160 … OP_EQUALVERIFY OP_CHECKSIG OP_ENDIF OP_ENDIF`; $\mathrm{numBytes}(32) = [0\mathrm{x}01, 0\mathrm{x}20]$ and $\mathrm{numBytes}(2) = [0\mathrm{x}52]$). $\mathrm{RecB}(r, K_r, K_l, h, e)$ is the byte string

$$[0\mathrm{x}76, 0\mathrm{xa}9] \mathbin{+\!\!+} \mathrm{pushBytes}(r) \mathbin{+\!\!+} [0\mathrm{x}87, 0\mathrm{x}63, 0\mathrm{xac}, 0\mathrm{x}67] \mathbin{+\!\!+} \mathrm{pushBytes}(K_r) \mathbin{+\!\!+} [0\mathrm{x}7\mathrm{c}, 0\mathrm{x}82] \mathbin{+\!\!+} \mathrm{numBytes}(32) \mathbin{+\!\!+} [0\mathrm{x}87, 0\mathrm{x}63, 0\mathrm{xa}9] \mathbin{+\!\!+} \mathrm{pushBytes}(h) \mathbin{+\!\!+} [0\mathrm{x}88] \mathbin{+\!\!+} \mathrm{numBytes}(2) \mathbin{+\!\!+} [0\mathrm{x}7\mathrm{c}] \mathbin{+\!\!+} \mathrm{pushBytes}(K_l) \mathbin{+\!\!+} \mathrm{numBytes}(2) \mathbin{+\!\!+} [0\mathrm{xae}, 0\mathrm{x}67, 0\mathrm{x}75] \mathbin{+\!\!+} \mathrm{numBytes}(e) \mathbin{+\!\!+} [0\mathrm{xb}1, 0\mathrm{x}75, 0\mathrm{xac}, 0\mathrm{x}68, 0\mathrm{x}68]$$

(`… OP_EQUAL OP_IF OP_HASH160 … OP_EQUALVERIFY … OP_SWAP … OP_CHECKMULTISIG OP_ELSE OP_DROP <e> OP_CHECKLOCKTIMEVERIFY OP_DROP OP_CHECKSIG OP_ENDIF OP_ENDIF`), where $\mathrm{numBytes}(e)$ is the single byte $e + 0\mathrm{x}50$ if $e = -1$ or $1 \le e \le 16$ and $\mathrm{pushBytes}(\mathrm{ser}(e))$ otherwise.

**The two witness scripts as instruction lists.** Writing $\langle d\rangle$ for the data push of the byte string $d$, the *offered script* $\mathrm{Off}(r, K_r, K_l, h)$, for byte strings $r$ (the "revocation hash"), $K_r$ (the "remote key"), $K_l$ (the "local key") and $h$ (the "payment hash"), all four being completely unconstrained parameters (any byte strings, not necessarily 20 bytes, not necessarily hashes of anything), is the 26-instruction list

$$\begin{aligned}&\texttt{OP\_DUP}\ \texttt{OP\_HASH160}\ \langle r\rangle\ \texttt{OP\_EQUAL}\ \texttt{OP\_IF}\ \texttt{OP\_CHECKSIG}\ \texttt{OP\_ELSE}\ \langle K_r\rangle\ \texttt{OP\_SWAP}\ \texttt{OP\_SIZE}\ \langle[0\mathrm{x}20]\rangle\ \texttt{OP\_EQUAL}\\ &\texttt{OP\_NOTIF}\ \texttt{OP\_DROP}\ \texttt{OP\_2}\ \texttt{OP\_SWAP}\ \langle K_l\rangle\ \texttt{OP\_2}\ \texttt{OP\_CHECKMULTISIG}\ \texttt{OP\_ELSE}\ \texttt{OP\_HASH160}\ \langle h\rangle\ \texttt{OP\_EQUALVERIFY}\ \texttt{OP\_CHECKSIG}\ \texttt{OP\_ENDIF}\ \texttt{OP\_ENDIF},\end{aligned}$$

where $\langle[0\mathrm{x}20]\rangle$ is $\mathrm{numInstr}(32)$ and `OP_2` is $\mathrm{numInstr}(2)$, the opcode byte $0\mathrm{x}52$. The *received script* $\mathrm{Rec}(r, K_r, K_l, h, e)$ additionally takes an integer $e$ (the "expiry", any integer, possibly negative or zero) and is the 28-instruction list

$$\begin{aligned}&\texttt{OP\_DUP}\ \texttt{OP\_HASH160}\ \langle r\rangle\ \texttt{OP\_EQUAL}\ \texttt{OP\_IF}\ \texttt{OP\_CHECKSIG}\ \texttt{OP\_ELSE}\ \langle K_r\rangle\ \texttt{OP\_SWAP}\ \texttt{OP\_SIZE}\ \langle[0\mathrm{x}20]\rangle\ \texttt{OP\_EQUAL}\\ &\texttt{OP\_IF}\ \texttt{OP\_HASH160}\ \langle h\rangle\ \texttt{OP\_EQUALVERIFY}\ \texttt{OP\_2}\ \texttt{OP\_SWAP}\ \langle K_l\rangle\ \texttt{OP\_2}\ \texttt{OP\_CHECKMULTISIG}\\ &\texttt{OP\_ELSE}\ \texttt{OP\_DROP}\ \mathrm{numInstr}(e)\ \texttt{OP\_CHECKLOCKTIMEVERIFY}\ \texttt{OP\_DROP}\ \texttt{OP\_CHECKSIG}\ \texttt{OP\_ENDIF}\ \texttt{OP\_ENDIF},\end{aligned}$$

where $\mathrm{numInstr}(e)$ is the opcode $e + 0\mathrm{x}50$ if $e = -1$ or $1\le e\le 16$, and the data push of $\mathrm{ser}(e)$ otherwise (the empty push when $e = 0$; a push carrying a sign bit when $e < -1$).

**Byte-level parsing $\mathrm{parse}(s)$.** $\mathrm{parse}$ reads a byte string instruction by instruction with a fuel of $|s|$ steps and yields $\mathrm{none}$ on any malformed push and $\mathrm{some}$ of the instruction list otherwise. One instruction is read from a first byte $b$ as follows: if $b \le 0\mathrm{x}4\mathrm{e}$ it is a data push, whose length is $b$ itself when $b < 0\mathrm{x}4\mathrm{c}$, the next one byte when $b = 0\mathrm{x}4\mathrm{c}$, the next two bytes little-endian when $b = 0\mathrm{x}4\mathrm{d}$, and the next four bytes little-endian when $b = 0\mathrm{x}4\mathrm{e}$ (failing if those length bytes are missing), and the push fails if fewer bytes than the announced length remain; otherwise ($b > 0\mathrm{x}4\mathrm{e}$) it is the non-push opcode $b$. The empty string parses to the empty instruction list.
