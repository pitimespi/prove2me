# Read-back: `BitcoinHtlc.received_spends_iff`

**Statement.** Let $f$ be any flag set, $o$ any oracle, $r, K_r, K_l, h$ any four byte strings with $|r| \le 520$, $|K_r| \le 520$, $|K_l| \le 520$, $|h| \le 520$, $e$ any integer with $|e| < 2^{32}$, and $\mathit{st}$ any list of byte strings (an initial stack, top first, of any length including zero, elements of any size). The theorem asserts

$$\Bigl(\exists\, \mathit{res},\ \mathrm{eval}_{f,o}\bigl(\mathit{st}, \mathrm{Rec}(r, K_r, K_l, h, e)\bigr) = \mathrm{some}\,\mathit{res}\ \land\ |\mathit{res}| = 1\ \land\ \mathrm{topTrue}(\mathit{res}) = \mathrm{true}\Bigr) \iff \mathrm{ReceivedSpend}(f, o, r, K_r, K_l, h, e, \mathit{st}),$$

where the left side says that the interpreter run with flags $f$ and oracle $o$ on $\mathit{st}$ and the received script does not fail, leaves exactly one element, and that element is $\mathrm{castToBool}$-true ($\mathrm{topTrue}$ is false on an empty stack and $\mathrm{castToBool}$ of the top otherwise), and the right side is the three-way disjunction unfolded below.

---

## Definitions unfolded

**Basic notions used throughout.** A *byte* is an 8-bit word and a *byte string* (written $\mathrm{Bytes}$) is a finite list of bytes; $|b|$ denotes the length of a byte string $b$. The constant $L_{\max} = 520$ is the interpreter's maximum size of one stack element. A *flag set* $f$ consists of three Booleans $f.\mathrm{cltv}$, $f.\mathrm{csv}$, $f.\mathrm{nulldummy}$. An *oracle* $o$ is an arbitrary structure supplying eight functions with no constraints whatsoever on their behaviour: $o.\mathrm{ripemd160}, o.\mathrm{sha1}, o.\mathrm{sha256}, o.\mathrm{hash160}, o.\mathrm{hash256} : \mathrm{Bytes}\to\mathrm{Bytes}$ (so in particular $o.\mathrm{hash160}$ is *any* function from byte strings to byte strings, not necessarily RIPEMD160$\circ$SHA256, not necessarily 20-byte-valued), $o.\mathrm{checkSig} : \mathrm{Bytes}\to\mathrm{Bytes}\to \mathrm{Option}\,\mathrm{Bool}$ (first argument the signature, second the public key; the value $\mathrm{none}$ represents a script-aborting failure, $\mathrm{some}\,b$ a verdict $b$), $o.\mathrm{checkLockTime} : \mathbb{Z}\to\mathrm{Bool}$ and $o.\mathrm{checkSequence} : \mathbb{Z}\to\mathrm{Bool}$. Stacks are lists written top element first. $\mathrm{castToBool}(b)$ is: false for the empty string; for a one-byte string $[x]$, true iff $x\neq 0$ and $x \neq 0\mathrm{x}80$; for $x :: r$ with $r$ non-empty, true iff $x\neq 0$ or $\mathrm{castToBool}(r)$ (so a string of zero bytes whose last byte is $0\mathrm{x}80$ is false). $\mathrm{boolBytes}(\mathrm{true}) = [0\mathrm{x}01]$ and $\mathrm{boolBytes}(\mathrm{false}) = []$ (the empty string). The script-number encoding $\mathrm{ser}(v)$ of an integer $v$ is: $[]$ if $v = 0$; otherwise the little-endian bytes of $|v|$ with no trailing zero byte, then, if the last of those bytes has its top bit ($0\mathrm{x}80$) set, an extra byte $0\mathrm{x}80$ (for $v<0$) or $0\mathrm{x}00$ (for $v>0$) is appended, and otherwise, for $v<0$, the top bit of the last byte is set. For example $\mathrm{ser}(2) = [0\mathrm{x}02]$ and $\mathrm{ser}(32) = [0\mathrm{x}20]$. The decoding $\mathrm{num}_k(b)$ ("script number of at most $k$ bytes, non-minimal encodings allowed") is $\mathrm{none}$ if $|b| > k$, and otherwise $\mathrm{some}$ of the little-endian value of $b$ with the top bit of the last byte read as a sign (the empty string decodes to $0$).

**The number push $\mathrm{numInstr}(n)$ / $\mathrm{numBytes}(n)$.** For an integer $n$, $\mathrm{numInstr}(n)$ is the single opcode with byte value $n + 0\mathrm{x}50$ when $n = -1$ or $1 \le n \le 16$ (so $\mathrm{numInstr}(-1)$ is the opcode $0\mathrm{x}4\mathrm{f}$, $\mathrm{numInstr}(2)$ is the opcode $0\mathrm{x}52$, i.e. `OP_2`), and otherwise it is the data push of $\mathrm{ser}(n)$ (so $\mathrm{numInstr}(32)$ is the push of the one-byte string $[0\mathrm{x}20]$, and $\mathrm{numInstr}(0)$ is the push of the empty string). $\mathrm{numBytes}(n)$ is the byte-level form: the one opcode byte $n + 0\mathrm{x}50$ in the first case, and $\mathrm{pushBytes}(\mathrm{ser}(n))$ otherwise, where $\mathrm{pushBytes}(d)$ is the canonical push encoding of a byte string $d$: $[\,|d|\,] \mathbin{+\!\!+} d$ if $|d| < 0\mathrm{x}4\mathrm{c}$; $[0\mathrm{x}4\mathrm{c}, |d|] \mathbin{+\!\!+} d$ if $|d| \le 0\mathrm{xff}$; $[0\mathrm{x}4\mathrm{d}] \mathbin{+\!\!+} (\text{2 little-endian bytes of } |d|) \mathbin{+\!\!+} d$ if $|d| \le 0\mathrm{xffff}$; and $[0\mathrm{x}4\mathrm{e}] \mathbin{+\!\!+} (\text{4 little-endian bytes of } |d|) \mathbin{+\!\!+} d$ otherwise.

**The two witness scripts as instruction lists.** Writing $\langle d\rangle$ for the data push of the byte string $d$, the *offered script* $\mathrm{Off}(r, K_r, K_l, h)$, for byte strings $r$ (the "revocation hash"), $K_r$ (the "remote key"), $K_l$ (the "local key") and $h$ (the "payment hash"), all four being completely unconstrained parameters (any byte strings, not necessarily 20 bytes, not necessarily hashes of anything), is the 26-instruction list

$$\begin{aligned}&\texttt{OP\_DUP}\ \texttt{OP\_HASH160}\ \langle r\rangle\ \texttt{OP\_EQUAL}\ \texttt{OP\_IF}\ \texttt{OP\_CHECKSIG}\ \texttt{OP\_ELSE}\ \langle K_r\rangle\ \texttt{OP\_SWAP}\ \texttt{OP\_SIZE}\ \langle[0\mathrm{x}20]\rangle\ \texttt{OP\_EQUAL}\\ &\texttt{OP\_NOTIF}\ \texttt{OP\_DROP}\ \texttt{OP\_2}\ \texttt{OP\_SWAP}\ \langle K_l\rangle\ \texttt{OP\_2}\ \texttt{OP\_CHECKMULTISIG}\ \texttt{OP\_ELSE}\ \texttt{OP\_HASH160}\ \langle h\rangle\ \texttt{OP\_EQUALVERIFY}\ \texttt{OP\_CHECKSIG}\ \texttt{OP\_ENDIF}\ \texttt{OP\_ENDIF},\end{aligned}$$

where $\langle[0\mathrm{x}20]\rangle$ is $\mathrm{numInstr}(32)$ and `OP_2` is $\mathrm{numInstr}(2)$, the opcode byte $0\mathrm{x}52$. The *received script* $\mathrm{Rec}(r, K_r, K_l, h, e)$ additionally takes an integer $e$ (the "expiry", any integer, possibly negative or zero) and is the 28-instruction list

$$\begin{aligned}&\texttt{OP\_DUP}\ \texttt{OP\_HASH160}\ \langle r\rangle\ \texttt{OP\_EQUAL}\ \texttt{OP\_IF}\ \texttt{OP\_CHECKSIG}\ \texttt{OP\_ELSE}\ \langle K_r\rangle\ \texttt{OP\_SWAP}\ \texttt{OP\_SIZE}\ \langle[0\mathrm{x}20]\rangle\ \texttt{OP\_EQUAL}\\ &\texttt{OP\_IF}\ \texttt{OP\_HASH160}\ \langle h\rangle\ \texttt{OP\_EQUALVERIFY}\ \texttt{OP\_2}\ \texttt{OP\_SWAP}\ \langle K_l\rangle\ \texttt{OP\_2}\ \texttt{OP\_CHECKMULTISIG}\\ &\texttt{OP\_ELSE}\ \texttt{OP\_DROP}\ \mathrm{numInstr}(e)\ \texttt{OP\_CHECKLOCKTIMEVERIFY}\ \texttt{OP\_DROP}\ \texttt{OP\_CHECKSIG}\ \texttt{OP\_ENDIF}\ \texttt{OP\_ENDIF},\end{aligned}$$

where $\mathrm{numInstr}(e)$ is the opcode $e + 0\mathrm{x}50$ if $e = -1$ or $1\le e\le 16$, and the data push of $\mathrm{ser}(e)$ otherwise (the empty push when $e = 0$; a push carrying a sign bit when $e < -1$).

**The interpreter $\mathrm{eval}_{f,o}(\mathit{st}, \mathit{script})$.** This is the transcription of Bitcoin Core's legacy `EvalScript`: starting from the state (main stack $\mathit{st}$, empty alt stack, empty condition stack, operation count $0$), it processes the instructions of $\mathit{script}$ in order and returns $\mathrm{none}$ ("script failure") or $\mathrm{some}$ of the final main stack. One instruction is processed as follows. A data push of $d$ fails if $|d| > 520$; otherwise $d$ is pushed onto the main stack when every entry of the condition stack is true (otherwise the state is unchanged), and the step fails if the main and alt stacks then hold more than $1000$ elements together. An opcode $c$ is "counted" when $c > 0\mathrm{x}60$ (`OP_16`); a counted opcode fails if the count already equals $201$, and otherwise increments the count; any of the fifteen disabled opcodes (`OP_CAT`, `OP_SUBSTR`, `OP_LEFT`, `OP_RIGHT`, `OP_INVERT`, `OP_AND`, `OP_OR`, `OP_XOR`, `OP_2MUL`, `OP_2DIV`, `OP_MUL`, `OP_DIV`, `OP_MOD`, `OP_LSHIFT`, `OP_RSHIFT`) fails even when not executed; then, if every entry of the condition stack is true ("executing") or $c$ is one of `OP_IF`, `OP_NOTIF`, `OP_ELSE`, `OP_ENDIF` (any byte from $0\mathrm{x}63$ to $0\mathrm{x}68$ inclusive, which also includes the bytes $0\mathrm{x}65$ and $0\mathrm{x}66$, for which execution fails), the opcode is executed and the 1000-element stack bound re-checked; an unexecuted opcode leaves the state alone. After the last instruction the run fails if the condition stack is non-empty. The executed opcodes relevant here behave as follows (with "fail" meaning $\mathrm{none}$): `OP_1`…`OP_16` push $\mathrm{ser}(c - 0\mathrm{x}50)$ (so `OP_2` pushes $[0\mathrm{x}02]$; these are not counted); `OP_DUP` fails on an empty stack and otherwise duplicates the top; `OP_DROP` fails on an empty stack and otherwise removes the top; `OP_SWAP` fails with fewer than two elements and otherwise exchanges the top two; `OP_SIZE` fails on an empty stack and otherwise pushes $\mathrm{ser}(|\mathrm{top}|)$ above the unchanged top; `OP_HASH160` fails on an empty stack and otherwise replaces the top $t$ by $o.\mathrm{hash160}(t)$; `OP_EQUAL` fails with fewer than two elements and otherwise pops the top two $a$ (top) and $b$ and pushes $\mathrm{boolBytes}(b = a)$ (byte-string equality), while `OP_EQUALVERIFY` pops them and fails unless $b = a$; `OP_IF` (resp. `OP_NOTIF`), when executing, fails on an empty stack and otherwise pops the top $t$ and pushes $\mathrm{castToBool}(t)$ (resp. its negation) onto the condition stack, and when not executing pushes false onto the condition stack without touching the main stack; `OP_ELSE` fails on an empty condition stack and otherwise negates its top; `OP_ENDIF` fails on an empty condition stack and otherwise pops it; `OP_CHECKSIG` fails with fewer than two elements and otherwise pops $\mathit{pk}$ (top) and $\mathit{sig}$, fails if $o.\mathrm{checkSig}(\mathit{sig}, \mathit{pk}) = \mathrm{none}$, and pushes $\mathrm{boolBytes}(b)$ if it is $\mathrm{some}\,b$; `OP_CHECKLOCKTIMEVERIFY` is a no-op if $f.\mathrm{cltv}$ is false, and otherwise fails on an empty stack, decodes the top as $\mathrm{num}_5$ (failing if it has more than $5$ bytes), fails if the value $n$ is negative or $o.\mathrm{checkLockTime}(n)$ is false, and otherwise leaves the state unchanged (the operand stays on the stack); `OP_CHECKMULTISIG` fails on an empty stack and otherwise pops $n_k$ decoded as $\mathrm{num}_4$ (failing if undecodable, negative or $> 20$), adds the value to the operation count (failing if that exceeds $201$), takes exactly that many keys from the stack (failing if too few), pops $n_s$ decoded as $\mathrm{num}_4$ (failing if undecodable, negative or $> n_k$), takes exactly that many signatures (failing if too few), computes $\mathrm{msLoop}_o(\mathit{sigs}, \mathit{keys})$ (failing if it is $\mathrm{none}$), then pops one more element $\mathit{dummy}$ (failing if the stack is empty), fails if $f.\mathrm{nulldummy}$ is true and $\mathit{dummy}$ is non-empty, and finally pushes $\mathrm{boolBytes}$ of the loop's verdict.

**The multisignature matching loop.** $\mathrm{msLoop}_o(\mathit{sigs}, \mathit{keys})$, for lists of signatures and keys (top first), is defined by recursion: it is $\mathrm{some}\,\mathrm{true}$ when $\mathit{sigs}$ is empty; $\mathrm{some}\,\mathrm{false}$ when $\mathit{sigs}$ is non-empty and $\mathit{keys}$ is empty; and for $\mathit{sigs} = s :: S$, $\mathit{keys} = k :: K$ it evaluates $o.\mathrm{checkSig}(s, k)$: if that is $\mathrm{none}$ the loop is $\mathrm{none}$; if it is $\mathrm{some}\,\mathrm{true}$ the loop is $\mathrm{some}\,\mathrm{false}$ when $|K| < |S|$ and otherwise $\mathrm{msLoop}_o(S, K)$; if it is $\mathrm{some}\,\mathrm{false}$ the loop is $\mathrm{some}\,\mathrm{false}$ when $|K| < |S| + 1$ and otherwise $\mathrm{msLoop}_o(s :: S, K)$. Unfolded on exactly two signatures and two keys, $\mathrm{msLoop}_o([s_1, s_2], [k_1, k_2])$ is: $\mathrm{none}$ if $o.\mathrm{checkSig}(s_1, k_1) = \mathrm{none}$; $\mathrm{some}\,\mathrm{false}$ if $o.\mathrm{checkSig}(s_1, k_1) = \mathrm{some}\,\mathrm{false}$ (since $1 < 2$; the second signature is then never checked); and if $o.\mathrm{checkSig}(s_1, k_1) = \mathrm{some}\,\mathrm{true}$ it is $\mathrm{none}$, $\mathrm{some}\,\mathrm{true}$ or $\mathrm{some}\,\mathrm{false}$ according as $o.\mathrm{checkSig}(s_2, k_2)$ is $\mathrm{none}$, $\mathrm{some}\,\mathrm{true}$ or $\mathrm{some}\,\mathrm{false}$.

**The lock-time predicate.** $\mathrm{CltvPasses}(f, o, e)$, for a flag set $f$, an oracle $o$ and an integer $e$, is the proposition

$$f.\mathrm{cltv} = \mathrm{false}\ \lor\ \bigl(0 \le e\ \land\ o.\mathrm{checkLockTime}(e) = \mathrm{true}\bigr),$$

so it holds unconditionally when the `cltv` flag is off, and otherwise requires $e$ non-negative and the oracle's lock-time check to accept $e$.

**The spend predicates.** $\mathrm{OfferedSpend}(f, o, r, K_r, K_l, h, \mathit{st})$, for a flag set $f$, an oracle $o$, byte strings $r, K_r, K_l, h$ and a list of byte strings $\mathit{st}$ (a stack, top first), is the disjunction of the following three propositions:

1. (revocation form) there exist byte strings $\mathit{pk}, \mathit{sig}$ with $\mathit{st} = [\mathit{pk}, \mathit{sig}]$, $o.\mathrm{hash160}(\mathit{pk}) = r$ and $o.\mathrm{checkSig}(\mathit{sig}, \mathit{pk}) = \mathrm{some}\,\mathrm{true}$;
2. (preimage form) there exist byte strings $\mathit{pre}, \mathit{sig}$ with $\mathit{st} = [\mathit{pre}, \mathit{sig}]$, $o.\mathrm{hash160}(\mathit{pre}) \ne r$, $|\mathit{pre}| = 32$, $o.\mathrm{hash160}(\mathit{pre}) = h$ and $o.\mathrm{checkSig}(\mathit{sig}, K_r) = \mathrm{some}\,\mathrm{true}$;
3. (timeout form) there exist byte strings $x, \sigma_l, \sigma_r, d$ with $\mathit{st} = [x, \sigma_l, \sigma_r, d]$, $o.\mathrm{hash160}(x) \ne r$, $|x| \ne 32$, $\mathrm{msLoop}_o([\sigma_l, \sigma_r], [K_l, K_r]) = \mathrm{some}\,\mathrm{true}$, and ($f.\mathrm{nulldummy} = \mathrm{true}$ implies $d = []$).

In particular the predicate is false whenever $\mathit{st}$ has a length other than $2$ or $4$ (e.g. the empty stack), and no size bound is placed on $\mathit{pk}, \mathit{sig}, \mathit{pre}, x, \sigma_l, \sigma_r, d$ by the predicate itself. $\mathrm{ReceivedSpend}(f, o, r, K_r, K_l, h, e, \mathit{st})$, with additionally an integer $e$, is the disjunction of:

1. (revocation form) there exist $\mathit{pk}, \mathit{sig}$ with $\mathit{st} = [\mathit{pk}, \mathit{sig}]$, $o.\mathrm{hash160}(\mathit{pk}) = r$ and $o.\mathrm{checkSig}(\mathit{sig}, \mathit{pk}) = \mathrm{some}\,\mathrm{true}$;
2. (success form) there exist $\mathit{pre}, \sigma_l, \sigma_r, d$ with $\mathit{st} = [\mathit{pre}, \sigma_l, \sigma_r, d]$, $o.\mathrm{hash160}(\mathit{pre}) \ne r$, $|\mathit{pre}| = 32$, $o.\mathrm{hash160}(\mathit{pre}) = h$, $\mathrm{msLoop}_o([\sigma_l, \sigma_r], [K_l, K_r]) = \mathrm{some}\,\mathrm{true}$, and ($f.\mathrm{nulldummy} = \mathrm{true}$ implies $d = []$);
3. (timeout form) there exist $x, \mathit{sig}$ with $\mathit{st} = [x, \mathit{sig}]$, $o.\mathrm{hash160}(x) \ne r$, $|x| \ne 32$, $\mathrm{CltvPasses}(f, o, e)$ and $o.\mathrm{checkSig}(\mathit{sig}, K_r) = \mathrm{some}\,\mathrm{true}$.
