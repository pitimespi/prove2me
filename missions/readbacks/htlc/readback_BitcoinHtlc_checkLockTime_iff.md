# Read-back: `BitcoinHtlc.checkLockTime_iff`

**Statement.** Let $\mathit{tx}$ be any transaction, i.e. a record with a version (a natural number), a list $\mathit{tx}.\mathrm{vin}$ of inputs (each input a record with a previous outpoint, a scriptSig byte string, a natural number `nSequence` and a witness list), a list of outputs, and a natural number $\mathit{tx}.\mathrm{nLockTime}$ (no upper bound such as $2^{32}$ is assumed on it here). Let $n$ be any natural number (an input index, possibly out of range) and $e$ any integer satisfying the two hypotheses $0 \le e$ and $e < 500\,000\,000$. Then the theorem asserts the equivalence

$$\mathrm{CLT}(\mathit{tx}, n, e) = \mathrm{true} \iff \mathit{tx}.\mathrm{nLockTime} < 500\,000\,000\ \land\ e \le \mathit{tx}.\mathrm{nLockTime}\ \land\ \mathrm{seq}(\mathit{tx}, n) \ne 0\mathrm{xffffffff},$$

where the comparison $e \le \mathit{tx}.\mathrm{nLockTime}$ is between integers (the natural number cast to $\mathbb{Z}$), and the two functions are as follows. $\mathrm{seq}(\mathit{tx}, n)$ ("input sequence") is the `nSequence` field of the $n$-th input of $\mathit{tx}$ (0-based) when $n < |\mathit{tx}.\mathrm{vin}|$, and otherwise the `nSequence` of a default input, which is $0$. $\mathrm{CLT}(\mathit{tx}, n, t)$ is the transcription of Bitcoin Core's `CheckLockTime` as a Boolean function of the transaction, the input index and an integer operand $t$: it is false unless either ($\mathit{tx}.\mathrm{nLockTime} < 500\,000\,000$ and $t < 500\,000\,000$) or ($500\,000\,000 \le \mathit{tx}.\mathrm{nLockTime}$ and $500\,000\,000 \le t$); otherwise it is false if $\mathit{tx}.\mathrm{nLockTime} < t$ (as integers); otherwise it is false if the `nSequence` of the $n$-th input, with the same out-of-range default input (`nSequence` $0$), equals $0\mathrm{xffffffff} = 4\,294\,967\,295$; and otherwise it is true. Nothing else is assumed about $\mathit{tx}$ or $n$; in particular when $n \ge |\mathit{tx}.\mathrm{vin}|$ both sides refer to the default sequence value $0$.
