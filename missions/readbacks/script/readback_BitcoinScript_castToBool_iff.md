# Read-back: `BitcoinScript.castToBool_iff`

**Binders and hypothesis.** There is a single universally quantified variable $v$, a finite list of bytes (8-bit words), of any length including zero. There are no hypotheses, no flags, no oracle, and no other parameters.

**Conclusion.** The statement is a biconditional between two Boolean/propositional facts about $v$:
$$\mathrm{castToBool}(v) = \text{true} \quad\Longleftrightarrow\quad \mathrm{setVch}(v) \neq 0 .$$

**Unfolding the left-hand side.** $\mathrm{castToBool}$ is the recursive function with $\mathrm{castToBool}([]) = \text{false}$; $\mathrm{castToBool}([b]) = (b \neq 0 \wedge b \neq \mathtt{0x80})$ for a single byte; and $\mathrm{castToBool}(b :: r) = (b \neq 0) \vee \mathrm{castToBool}(r)$ when $r$ is non-empty. Spelled out: $\mathrm{castToBool}(v)$ is true exactly when there is some byte of $v$ that is non-zero, except in the special case where every byte before the last is $\mathtt{0x00}$ and the last byte is exactly $\mathtt{0x80}$, which is false. In particular $[\mathtt{0x80}]$, $[\mathtt{0x00},\mathtt{0x80}]$, $[]$, and $[\mathtt{0x00},\mathtt{0x00}]$ are all false, while $[\mathtt{0x80},\mathtt{0x00}]$, $[\mathtt{0x01}]$ and $[\mathtt{0x00},\mathtt{0x01}]$ are true.

**Unfolding the right-hand side.** $\mathrm{setVch}(v)$ is the integer
$$\mathrm{setVch}(v) = \begin{cases} -\,\mathrm{leNat}(\mathrm{clearTop}(v)) & \text{if the top bit } \mathtt{0x80} \text{ of the last byte of } v \text{ is set,} \\ \phantom{-}\mathrm{leNat}(v) & \text{otherwise (including } v = []),\end{cases}$$
where $\mathrm{leNat}$ is the little-endian unsigned value ($\mathrm{leNat}(b :: r) = b + 256\cdot\mathrm{leNat}(r)$, $\mathrm{leNat}([]) = 0$) and $\mathrm{clearTop}$ clears bit $\mathtt{0x80}$ of the last byte only. Hence $\mathrm{setVch}(v) = 0$ exactly when every byte of $v$ is $\mathtt{0x00}$ after ignoring the sign bit of the last byte — i.e. when $v$ is empty, or all-zero, or all-zero except that its last byte is $\mathtt{0x80}$. The right-hand side $\mathrm{setVch}(v) \neq 0$ is the negation of that: some byte of $v$ has a bit set other than the sign bit of the final byte.

**The claim, in words.** For every byte list $v$, the truthiness test (some non-zero byte, with "negative zero" $0\cdots0\,\mathtt{0x80}$ counted as false) coincides with the numeric value under the sign-magnitude little-endian reading being non-zero. Both directions are asserted: whenever the Boolean test is true the integer is non-zero, and whenever the integer is non-zero the Boolean test is true. Equivalently, $\mathrm{castToBool}(v) = \text{false}$ if and only if $\mathrm{setVch}(v) = 0$.

**Edge cases included by the quantifier.** $v = []$ (both sides false: $\mathrm{castToBool}([]) = \text{false}$ and $\mathrm{setVch}([]) = 0$). $v = [\mathtt{0x80}]$ (both sides false: the single-byte clause excludes $\mathtt{0x80}$, and $\mathrm{setVch}([\mathtt{0x80}]) = -\mathrm{leNat}([\mathtt{0x00}]) = 0$). Lists of arbitrary length, including lists far longer than any numeric size limit used elsewhere in the file (4 or 5 bytes): the statement does not restrict length, so it concerns $\mathrm{setVch}$ on lists of, say, 1000 bytes just as much as on short ones. Lists with trailing zero bytes such as $[\mathtt{0x01},\mathtt{0x00}]$ (both sides true) and non-minimal encodings are all included.

**What is not said.** The theorem does not mention `toNum`, minimal encodings, `nonMinimal`, or any size limit; it says nothing about how $v$ was produced, and nothing about `serialize`. It does not assert that $\mathrm{castToBool}(v)$ equals $\mathrm{castToBool}(\mathrm{serialize}(\mathrm{setVch}(v)))$ or any round-trip property. It does not say which non-zero value $\mathrm{setVch}(v)$ takes, only that it is non-zero; in particular it does not relate the sign or magnitude of $\mathrm{setVch}(v)$ to anything. It does not state the contrapositive form separately, though that follows logically from the biconditional. It makes no claim about the interpreter (`execOp`, `step`, `run`) or about how the result of `castToBool` is used by `OP_IF`, `OP_VERIFY`, `OP_IFDUP` or `verifyScriptPlain`; in particular it does not assert that a script's final truth value is determined by a numeric value. It does not involve any oracle or flags.
