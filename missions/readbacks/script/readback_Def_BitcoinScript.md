# Read-back: `Def_BitcoinScript`

This file introduces, inside a namespace `BitcoinScript`, a model of a stack-machine script interpreter: numeric encodings on byte lists, a parsed-instruction type, opcode constants, an abstract "oracle" of external primitives, a machine state, a one-instruction executor, a loop over a script, and a two-script verification predicate. Everything below describes the code exactly as written, declaration by declaration, in file order. Throughout, a **byte** is an 8-bit word (written in hexadecimal, e.g. $\mathtt{0x80}$), a **byte list** is a finite sequence of bytes, and **stacks are written top element first**: the head of the list is the top of the stack.

**Type abbreviations.** `Byte` is the type of 8-bit words (bit-vectors of width 8); `Bytes` is the type of finite lists of such bytes. Later, `Script` abbreviates finite lists of instructions (see `Instr`).

**Constants.** Five natural-number constants are fixed: $\mathrm{MAX\_SCRIPT\_ELEMENT\_SIZE} = 520$, $\mathrm{MAX\_OPS\_PER\_SCRIPT} = 201$, $\mathrm{MAX\_PUBKEYS\_PER\_MULTISIG} = 20$, $\mathrm{MAX\_STACK\_SIZE} = 1000$, and $\mathrm{nDefaultMaxNumSize} = 4$. Later, $\mathrm{SEQUENCE\_LOCKTIME\_DISABLE\_FLAG} = 2147483648 = 2^{31}$ is also a natural number.

## Numeric encoding (`CScriptNum` section)

**`leNat`** (byte list $\to$ natural number). The little-endian unsigned value: $\mathrm{leNat}([]) = 0$ and $\mathrm{leNat}(b :: r) = b + 256\cdot \mathrm{leNat}(r)$, where $b$ is read as a number in $[0,255]$. The *first* byte of the list is the least significant. Trailing zero bytes do not change the value; there is no bound on the length.

**`topBit`** (byte list $\to$ Boolean). Whether the most significant bit ($\mathtt{0x80}$) of the **last** byte is set: false for the empty list; for a one-element list $[b]$ it is $(b \,\&\, \mathtt{0x80}) \neq 0$; for a longer list it recurses on the tail, so only the final byte matters.

**`clearTop`** (byte list $\to$ byte list). Clears bit $\mathtt{0x80}$ of the last byte: the empty list is unchanged, $[b] \mapsto [b \,\&\, \mathtt{0x7f}]$, and for longer lists the head is kept and the tail is processed recursively. The length is preserved.

**`setVch`** (byte list $\to$ integer). The signed value of a byte list:
$$\mathrm{setVch}(v) = \begin{cases} -\,\mathrm{leNat}(\mathrm{clearTop}(v)) & \text{if } \mathrm{topBit}(v) \\ \phantom{-}\mathrm{leNat}(v) & \text{otherwise.}\end{cases}$$
So the top bit of the last byte is a sign bit and the remaining bits form a little-endian magnitude. Edge cases: $\mathrm{setVch}([]) = 0$; $\mathrm{setVch}([\mathtt{0x80}]) = -0 = 0$ (negative zero is the integer $0$); $\mathrm{setVch}([\mathtt{0x00},\mathtt{0x80}]) = 0$ likewise; any list all of whose bytes are $\mathtt{0x00}$ except possibly a sign bit on the last byte has value $0$. There is no length restriction and no minimality requirement.

**`natBytes`** (natural number $\to$ byte list). Little-endian bytes of a natural number with no trailing zero bytes: $\mathrm{natBytes}(0) = []$, and for $n \neq 0$ it is $(n \bmod 256) :: \mathrm{natBytes}(\lfloor n/256\rfloor)$ (the byte being the 8-bit word of $n \bmod 256$). Termination is by $n$ decreasing. The last byte of a non-empty result is never $\mathtt{0x00}$.

**`setTop`** (byte list $\to$ byte list). Sets bit $\mathtt{0x80}$ of the last byte: $[] \mapsto []$, $[b] \mapsto [b \,|\, \mathtt{0x80}]$, head kept and tail processed otherwise.

**`serialize`** (integer $\to$ byte list). The encoding of an integer $v$:
- if $v = 0$: the empty list;
- otherwise let $\mathit{neg} := (v < 0)$ and $\mathit{mag} := \mathrm{natBytes}(|v|)$ (non-empty since $v \ne 0$). If $\mathrm{topBit}(\mathit{mag})$ holds (the last magnitude byte already has bit $\mathtt{0x80}$ set), append one extra byte: $\mathtt{0x80}$ if $\mathit{neg}$, else $\mathtt{0x00}$. If the top bit is clear and $\mathit{neg}$, return $\mathrm{setTop}(\mathit{mag})$. If the top bit is clear and $v > 0$, return $\mathit{mag}$ unchanged.

Examples implied by the code: $1 \mapsto [\mathtt{0x01}]$; $-1 \mapsto [\mathtt{0x81}]$; $127 \mapsto [\mathtt{0x7f}]$; $128 \mapsto [\mathtt{0x80},\mathtt{0x00}]$; $-128 \mapsto [\mathtt{0x80},\mathtt{0x80}]$; $255 \mapsto [\mathtt{0xff},\mathtt{0x00}]$; $256 \mapsto [\mathtt{0x00},\mathtt{0x01}]$. There is no upper bound on $|v|$ or on the output length.

**`nonMinimal`** (byte list $\to$ Boolean; "true means non-minimal"). Reverse the list. If it is empty, the result is **false** (the empty list is treated as minimal). Otherwise write it as $\mathit{last} :: \mathit{before}$ (so $\mathit{last}$ is the final byte of $v$ and $\mathit{before}$ is the rest of $v$, reversed). The result is
$$\big((\mathit{last} \,\&\, \mathtt{0x7f}) = 0\big) \;\wedge\; \begin{cases}\text{true} & \text{if } \mathit{before} = [] \\ (\mathit{prev} \,\&\, \mathtt{0x80}) = 0 & \text{if } \mathit{before} = \mathit{prev} :: \_\end{cases}$$
where $\mathit{prev}$ is the second-to-last byte of $v$. In words: $v$ is non-minimal exactly when its last byte carries no value bits (it is $\mathtt{0x00}$ or $\mathtt{0x80}$) and either it is the only byte or the preceding byte has its top bit clear. Consequences: $[\mathtt{0x00}]$ and $[\mathtt{0x80}]$ are non-minimal; $[\mathtt{0x01},\mathtt{0x00}]$ is non-minimal; $[\mathtt{0x80},\mathtt{0x00}]$ and $[\mathtt{0x80},\mathtt{0x80}]$ are minimal; $[]$ is minimal.

**`toNum`** (Boolean `requireMinimal`, natural `maxSize`, byte list $v$ $\to$ optional integer). Returns "no value" (failure) if $\mathrm{maxSize} < |v|$ (strict: a list of length exactly $\mathrm{maxSize}$ is accepted); otherwise failure if `requireMinimal` is true **and** $v$ is non-empty **and** $\mathrm{nonMinimal}(v)$ is true; otherwise the value $\mathrm{setVch}(v)$. (The non-emptiness conjunct is redundant with `nonMinimal`, which is already false on the empty list.) Note that with `requireMinimal = false` any byte list up to the size limit is accepted, including negative zero and padded encodings.

**`castToBool`** (byte list $\to$ Boolean). $\mathrm{castToBool}([]) = \text{false}$; for a single byte, $\mathrm{castToBool}([b]) = (b \ne 0 \wedge b \ne \mathtt{0x80})$; for $b :: \mathit{rest}$ with $\mathit{rest}$ non-empty, $\mathrm{castToBool}(b :: \mathit{rest}) = (b \ne 0) \vee \mathrm{castToBool}(\mathit{rest})$. Thus the list is "true" iff some byte is non-zero, except that a list consisting of zero bytes followed by a final $\mathtt{0x80}$ is "false". For example $[\mathtt{0x80}]$ and $[\mathtt{0x00},\mathtt{0x80}]$ are false, but $[\mathtt{0x80},\mathtt{0x00}]$ is true (its first byte is non-zero).

**`vchTrue`, `vchFalse`, `boolBytes`.** $\mathrm{vchTrue} = [\mathtt{0x01}]$, $\mathrm{vchFalse} = []$, and $\mathrm{boolBytes}(b)$ is $\mathrm{vchTrue}$ if $b$ is true, else $\mathrm{vchFalse}$.

## Scripts and opcodes

**`Instr`** (inductive type). A parsed instruction is either $\mathrm{push}(d)$ for a byte list $d$ (a data push; the opcode byte that produced it is not recorded, so e.g. an empty push and any other way of pushing the same bytes are the same instruction), or $\mathrm{op}(c)$ for a byte $c$ (a non-push opcode). The type has decidable equality. Nothing in the type prevents $\mathrm{op}(c)$ for small $c$ (the push range): the accompanying comment says such a value "behaves like an unknown opcode", and the executor below indeed sends it to the catch-all failure branch. `Script` is a list of instructions.

**Opcode constants.** Named bytes: $\mathrm{OP\_1NEGATE} = \mathtt{0x4f}$, $\mathrm{OP\_RESERVED} = \mathtt{0x50}$, $\mathrm{OP\_1} = \mathtt{0x51}$, $\mathrm{OP\_16} = \mathtt{0x60}$, $\mathrm{OP\_NOP} = \mathtt{0x61}$, $\mathrm{OP\_IF} = \mathtt{0x63}$, $\mathrm{OP\_NOTIF} = \mathtt{0x64}$, $\mathrm{OP\_ELSE} = \mathtt{0x67}$, $\mathrm{OP\_ENDIF} = \mathtt{0x68}$, $\mathrm{OP\_VERIFY} = \mathtt{0x69}$, $\mathrm{OP\_RETURN} = \mathtt{0x6a}$, then the stack operations $\mathtt{0x6b}$–$\mathtt{0x7d}$ (TOALTSTACK, FROMALTSTACK, 2DROP, 2DUP, 3DUP, 2OVER, 2ROT, 2SWAP, IFDUP, DEPTH, DROP, DUP, NIP, OVER, PICK, ROLL, ROT, SWAP, TUCK), the splice/bitwise bytes $\mathtt{0x7e}$–$\mathtt{0x88}$ (CAT, SUBSTR, LEFT, RIGHT, SIZE, INVERT, AND, OR, XOR, EQUAL, EQUALVERIFY), the arithmetic bytes $\mathtt{0x8b}$–$\mathtt{0xa5}$ (1ADD, 1SUB, 2MUL, 2DIV, NEGATE, ABS, NOT, 0NOTEQUAL, ADD, SUB, MUL, DIV, MOD, LSHIFT, RSHIFT, BOOLAND, BOOLOR, NUMEQUAL, NUMEQUALVERIFY, NUMNOTEQUAL, LESSTHAN, GREATERTHAN, LESSTHANOREQUAL, GREATERTHANOREQUAL, MIN, MAX, WITHIN), the crypto bytes $\mathtt{0xa6}$–$\mathtt{0xaf}$ (RIPEMD160, SHA1, SHA256, HASH160, HASH256, CODESEPARATOR, CHECKSIG, CHECKSIGVERIFY, CHECKMULTISIG, CHECKMULTISIGVERIFY), and $\mathrm{OP\_NOP1} = \mathtt{0xb0}$, $\mathrm{OP\_CHECKLOCKTIMEVERIFY} = \mathtt{0xb1}$, $\mathrm{OP\_CHECKSEQUENCEVERIFY} = \mathtt{0xb2}$, $\mathrm{OP\_NOP4} = \mathtt{0xb3}$, $\mathrm{OP\_NOP10} = \mathtt{0xb9}$. Bytes **not** given names include $\mathtt{0x62}$, $\mathtt{0x65}$, $\mathtt{0x66}$, $\mathtt{0x89}$, $\mathtt{0x8a}$ and everything from $\mathtt{0xba}$ upward; these matter below because the executor treats unnamed bytes by a catch-all.

**`isDisabled`** (byte $\to$ Boolean). True exactly for the fifteen bytes CAT, SUBSTR, LEFT, RIGHT, INVERT, AND, OR, XOR, 2MUL, 2DIV, MUL, DIV, MOD, LSHIFT, RSHIFT ($\mathtt{0x7e}$–$\mathtt{0x81}$, $\mathtt{0x83}$–$\mathtt{0x86}$, $\mathtt{0x8d}$, $\mathtt{0x8e}$, $\mathtt{0x95}$–$\mathtt{0x99}$). All of these are strictly greater than $\mathrm{OP\_16}$.

## Flags, oracle, state

**`Flags`** (structure). Three Booleans: `cltv`, `csv`, `nulldummy`. No other flag exists in the model; the comment says the policy flags (MINIMALDATA, NULLFAIL, CONST_SCRIPTCODE, DISCOURAGE_UPGRADABLE_NOPS, MINIMALIF) are modeled as permanently off.

**`Oracle`** (structure). Eight uninterpreted functions: `ripemd160`, `sha1`, `sha256`, `hash160`, `hash256`, each byte list $\to$ byte list (no constraint on output length or determinacy beyond being a function); `checkSig` : byte list $\to$ byte list $\to$ optional Boolean, with the first argument used as the signature and the second as the public key, where "no value" is documented as an encoding failure that fails the script and $\mathrm{some}(b)$ as the result of signature verification; `checkLockTime` : integer $\to$ Boolean; `checkSequence` : integer $\to$ Boolean. Any functions whatsoever may populate an oracle.

**`State`** (structure). Four fields: `stack` (list of byte lists, top first), `altstack` (same), `vfExec` (list of Booleans; the condition stack, most recent first), `opCount` (natural number). **`State.initial`**$(\mathit{stack}) = \langle \mathit{stack}, [], [], 0\rangle$: the given main stack, empty alt stack, empty condition stack, operation count zero.

**`allTrue`** (list of Booleans $\to$ Boolean). All entries are true; the empty list gives **true**.

**`pushNum`**$(s, n)$: the state $s$ with $\mathrm{serialize}(n)$ pushed on the main stack. **`eraseAt`**$(l, i)$: removes the element at index $i$ (0 = head/top); if $i$ is out of range the list is returned unchanged ($\mathrm{eraseAt}([], \_) = []$).

**`multisigLoop`**$(o, \mathit{sigs}, \mathit{keys})$ (optional Boolean), both lists top-first:
- $\mathit{sigs} = []$: $\mathrm{some}(\text{true})$ regardless of $\mathit{keys}$;
- $\mathit{sigs}$ non-empty and $\mathit{keys} = []$: $\mathrm{some}(\text{false})$;
- $\mathit{sig} :: \mathit{sigs}'$, $\mathit{key} :: \mathit{keys}'$: evaluate $o.\mathrm{checkSig}(\mathit{sig}, \mathit{key})$. If it is "no value", the whole result is "no value". If it is $\mathrm{some}(\text{true})$: if $|\mathit{keys}'| < |\mathit{sigs}'|$ return $\mathrm{some}(\text{false})$, else recurse on $(\mathit{sigs}', \mathit{keys}')$ (both consumed). If it is $\mathrm{some}(\text{false})$: if $|\mathit{keys}'| < |\mathit{sigs}'| + 1$ return $\mathrm{some}(\text{false})$, else recurse on $(\mathit{sig} :: \mathit{sigs}', \mathit{keys}')$ (only the key consumed).

So a signature is matched against successive keys; once the remaining keys are fewer than the remaining signatures the loop returns false **without** calling `checkSig` on the remaining pairs (so later encoding failures are not observed). Under the caller's invariant $|\mathit{sigs}| \le |\mathit{keys}|$ the second clause is never reached, but the function is defined for all inputs.

## `execOp` — executing one non-push opcode

**Signature.** $\mathrm{execOp}(f, o, \mathit{fExec}, c, s)$ takes flags $f$, oracle $o$, a Boolean $\mathit{fExec}$ (whether the current branch is being executed), an opcode byte $c$ and a state $s$, and returns an optional state; "no value" is script failure. The branches are tested **in the following order** (the first matching test wins); `execOp` itself does not change `opCount` except in the CHECKMULTISIG branch, does not consult `isDisabled`, and apart from the IF/NOTIF branch ignores $\mathit{fExec}$ entirely. In every branch, "the stack" is $s.\mathrm{stack}$ and "needs $k$ elements" means the branch returns failure when fewer than $k$ are present.

1. **$c = \mathrm{OP\_1NEGATE}$ or $\mathrm{OP\_1} \le c \le \mathrm{OP\_16}$.** Pushes $\mathrm{serialize}(c - \mathtt{0x50})$ computed in the integers: $-1$ for $\mathtt{0x4f}$, and $1,\dots,16$ for $\mathtt{0x51},\dots,\mathtt{0x60}$. No precondition. ($\mathrm{OP\_RESERVED} = \mathtt{0x50}$ is *not* in this range.)
2. **$\mathrm{OP\_NOP}$.** State unchanged.
3. **$\mathrm{OP\_CHECKLOCKTIMEVERIFY}$.** If $f.\mathrm{cltv}$ is false: state unchanged. Otherwise: empty stack $\Rightarrow$ failure; else let $n := \mathrm{toNum}(\text{false}, 5, \mathit{top})$ (up to 5 bytes, no minimality check); failure if that fails, failure if $n < 0$, failure if $o.\mathrm{checkLockTime}(n)$ is false; otherwise the state is returned **unchanged** (the top is not popped).
4. **$\mathrm{OP\_CHECKSEQUENCEVERIFY}$.** If $f.\mathrm{csv}$ is false: unchanged. Otherwise: empty stack $\Rightarrow$ failure; $n := \mathrm{toNum}(\text{false}, 5, \mathit{top})$, failure if that fails; failure if $n < 0$; if bit $2^{31}$ of $n$ (as a natural number) is set, the state is returned unchanged; else failure if $o.\mathrm{checkSequence}(n)$ is false, else unchanged.
5. **$\mathrm{OP\_NOP1}$ or $\mathrm{OP\_NOP4} \le c \le \mathrm{OP\_NOP10}$** ($\mathtt{0xb0}$, $\mathtt{0xb3}$–$\mathtt{0xb9}$). Unchanged.
6. **$\mathrm{OP\_IF}$ / $\mathrm{OP\_NOTIF}$.** If $\mathit{fExec}$: empty stack $\Rightarrow$ failure; else pop the top, let $v := \mathrm{castToBool}(\mathit{top})$, negated for NOTIF, and push $v$ onto `vfExec`. If not $\mathit{fExec}$: push **false** onto `vfExec`, stack untouched. There is no minimal-encoding requirement on the condition value.
7. **$\mathrm{OP\_ELSE}$.** Empty `vfExec` $\Rightarrow$ failure; else negate its head.
8. **$\mathrm{OP\_ENDIF}$.** Empty `vfExec` $\Rightarrow$ failure; else pop its head.
9. **$\mathrm{OP\_VERIFY}$.** Empty stack $\Rightarrow$ failure; if $\mathrm{castToBool}(\mathit{top})$ then pop it, else failure.
10. **$\mathrm{OP\_RETURN}$.** Failure.
11. **$\mathrm{OP\_TOALTSTACK}$** needs 1: moves the top to the head of the alt stack. **$\mathrm{OP\_FROMALTSTACK}$** needs a non-empty alt stack: moves its head to the top of the main stack.
12. **$\mathrm{OP\_2DROP}$** needs 2, drops both. **$\mathrm{OP\_2DUP}$**: $a,b,\ldots \mapsto a,b,a,b,\ldots$. **$\mathrm{OP\_3DUP}$**: $a,b,d \mapsto a,b,d,a,b,d$. **$\mathrm{OP\_2OVER}$** needs 4: $x_4,x_3,x_2,x_1 \mapsto x_2,x_1,x_4,x_3,x_2,x_1$. **$\mathrm{OP\_2ROT}$** needs 6: $x_6,\dots,x_1 \mapsto x_2,x_1,x_6,x_5,x_4,x_3$. **$\mathrm{OP\_2SWAP}$** needs 4: $x_4,x_3,x_2,x_1 \mapsto x_2,x_1,x_4,x_3$. (All written top-first.)
13. **$\mathrm{OP\_IFDUP}$** needs 1: duplicates the top iff $\mathrm{castToBool}(\mathit{top})$.
14. **$\mathrm{OP\_DEPTH}$**: pushes $\mathrm{serialize}(|\mathit{stack}|)$; no precondition.
15. **$\mathrm{OP\_DROP}$** needs 1; **$\mathrm{OP\_DUP}$** needs 1; **$\mathrm{OP\_NIP}$** needs 2: $a,\_ \mapsto a$; **$\mathrm{OP\_OVER}$** needs 2: $a,b \mapsto b,a,b$.
16. **$\mathrm{OP\_PICK}$ / $\mathrm{OP\_ROLL}$.** Stack must be $\mathit{top} :: \mathit{rest}$ with $\mathit{rest}$ non-empty (so at least 2 elements). $n := \mathrm{toNum}(\text{false}, 4, \mathit{top})$; failure if that fails, if $n < 0$, or if $|\mathit{rest}| \le n$. With $i := n$, let $v := \mathit{rest}[i]$ (always defined under these bounds; the unreachable out-of-range case is failure). ROLL yields $v :: \mathrm{eraseAt}(\mathit{rest}, i)$; PICK yields $v :: \mathit{rest}$. In both cases the count element $\mathit{top}$ is removed.
17. **$\mathrm{OP\_ROT}$** needs 3: $x_3,x_2,x_1 \mapsto x_1,x_3,x_2$. **$\mathrm{OP\_SWAP}$** needs 2: $a,b \mapsto b,a$. **$\mathrm{OP\_TUCK}$** needs 2: $x_2,x_1 \mapsto x_2,x_1,x_2$.
18. **$\mathrm{OP\_SIZE}$** needs 1: pushes $\mathrm{serialize}(|\mathit{top}|)$ **without** popping.
19. **$\mathrm{OP\_EQUAL}$ / $\mathrm{OP\_EQUALVERIFY}$** need 2: with stack $a :: b :: \mathit{rest}$, $\mathit{eq} := (b = a)$ as byte lists. EQUALVERIFY: if $\mathit{eq}$ the result stack is $\mathit{rest}$, else failure. EQUAL: $\mathrm{boolBytes}(\mathit{eq}) :: \mathit{rest}$.
20. **Unary arithmetic** ($\mathrm{OP\_1ADD}, \mathrm{OP\_1SUB}, \mathrm{OP\_NEGATE}, \mathrm{OP\_ABS}, \mathrm{OP\_NOT}, \mathrm{OP\_0NOTEQUAL}$) need 1: $n := \mathrm{toNum}(\text{false}, 4, \mathit{top})$, failure if undefined. Result $r$: $n+1$; $n-1$; $-n$; $|n|$; $[n = 0]$; $[n \ne 0]$ (Iverson brackets giving $1$ or $0$). The top is replaced by $\mathrm{serialize}(r)$.
21. **Binary arithmetic** ($\mathrm{OP\_ADD}, \mathrm{OP\_SUB}, \mathrm{OP\_BOOLAND}, \mathrm{OP\_BOOLOR}, \mathrm{OP\_NUMEQUAL}, \mathrm{OP\_NUMEQUALVERIFY}, \mathrm{OP\_NUMNOTEQUAL}, \mathrm{OP\_LESSTHAN}, \mathrm{OP\_GREATERTHAN}, \mathrm{OP\_LESSTHANOREQUAL}, \mathrm{OP\_GREATERTHANOREQUAL}, \mathrm{OP\_MIN}, \mathrm{OP\_MAX}$) need 2: with stack $a :: b :: \mathit{rest}$ ($a$ the top), $n_1 := \mathrm{toNum}(\text{false},4,b)$ (the **second** element) and $n_2 := \mathrm{toNum}(\text{false},4,a)$ (the **top**); failure if either is undefined. Then $r$ is $n_1+n_2$; $n_1-n_2$; $[n_1\ne0 \wedge n_2\ne0]$; $[n_1\ne0 \vee n_2\ne0]$; $[n_1=n_2]$ (for both NUMEQUAL and NUMEQUALVERIFY); $[n_1\ne n_2]$; $[n_1<n_2]$; $[n_1>n_2]$; $[n_1\le n_2]$; $[n_1\ge n_2]$; $\min(n_1,n_2)$; $\max(n_1,n_2)$. NUMEQUALVERIFY: if $r \ne 0$ the stack becomes $\mathit{rest}$, else failure. All others: $\mathrm{serialize}(r) :: \mathit{rest}$.
22. **$\mathrm{OP\_WITHIN}$** needs 3: with $a :: b :: d :: \mathit{rest}$, $n_1 := \mathrm{toNum}(\text{false},4,d)$ (third), $n_2$ from $b$ (second), $n_3$ from $a$ (top); failure if any is undefined; result $\mathrm{boolBytes}(n_2 \le n_1 \wedge n_1 < n_3) :: \mathit{rest}$ — i.e. "$x \in [\min, \max)$" with $x$ third from the top, $\min$ second, $\max$ on top. Note it pushes $\mathrm{boolBytes}$ directly.
23. **Hashes** ($\mathrm{OP\_RIPEMD160}, \mathrm{OP\_SHA1}, \mathrm{OP\_SHA256}, \mathrm{OP\_HASH160}, \mathrm{OP\_HASH256}$) need 1: the top is replaced by the corresponding oracle function applied to it. No size check on the result.
24. **$\mathrm{OP\_CODESEPARATOR}$.** Unchanged.
25. **$\mathrm{OP\_CHECKSIG}$ / $\mathrm{OP\_CHECKSIGVERIFY}$** need 2: with $\mathit{pubkey} :: \mathit{sig} :: \mathit{rest}$ (public key on **top**), evaluate $o.\mathrm{checkSig}(\mathit{sig}, \mathit{pubkey})$; "no value" $\Rightarrow$ failure. With $\mathrm{some}(\mathit{ok})$: CHECKSIGVERIFY gives $\mathit{rest}$ if $\mathit{ok}$, else failure; CHECKSIG gives $\mathrm{boolBytes}(\mathit{ok}) :: \mathit{rest}$. No "null-fail" rule is applied.
26. **$\mathrm{OP\_CHECKMULTISIG}$ / $\mathrm{OP\_CHECKMULTISIGVERIFY}$.** Empty stack $\Rightarrow$ failure. With $\mathit{nk} :: \mathit{rest}$: $n_K := \mathrm{toNum}(\text{false},4,\mathit{nk})$, failure if undefined, if $n_K < 0$, or if $20 < n_K$. Let $\mathit{opCount}' := s.\mathrm{opCount} + n_K$; failure if $201 < \mathit{opCount}'$. $\mathit{keys} :=$ the first $n_K$ elements of $\mathit{rest}$ (top-first), $\mathit{rest}$ advanced past them; failure if fewer than $n_K$ were available. Then the next element $\mathit{ns}$ must exist (else failure); $n_S := \mathrm{toNum}(\text{false},4,\mathit{ns})$, failure if undefined, if $n_S < 0$, or if $n_K < n_S$. $\mathit{sigs} :=$ the next $n_S$ elements, failure if fewer exist. Evaluate $\mathrm{multisigLoop}(o, \mathit{sigs}, \mathit{keys})$: "no value" $\Rightarrow$ failure; with $\mathrm{some}(\mathit{ok})$, one more element $\mathit{dummy}$ must exist (else failure); if $f.\mathrm{nulldummy}$ and $\mathit{dummy}$ is non-empty $\Rightarrow$ failure. The resulting state $s'$ has the remaining stack (dummy removed) and $\mathrm{opCount} := \mathit{opCount}'$. CHECKMULTISIGVERIFY returns $s'$ if $\mathit{ok}$, else failure; CHECKMULTISIG returns $s'$ with $\mathrm{boolBytes}(\mathit{ok})$ pushed. This is the **only** branch of `execOp` that modifies `opCount`.
27. **Anything else: failure.** This catch-all covers $\mathrm{OP\_RESERVED} = \mathtt{0x50}$, every byte $\le \mathtt{0x4e}$, $\mathtt{0x62}$, $\mathtt{0x65}$, $\mathtt{0x66}$, $\mathtt{0x89}$, $\mathtt{0x8a}$, every byte $\ge \mathtt{0xba}$, and the fifteen disabled bytes (if `execOp` were called on them directly).

## `step` — one loop iteration

$\mathrm{step}(f, o, s, i)$ returns an optional state.

**Push instruction $\mathrm{push}(d)$.** First, if $520 < |d|$ the result is failure — this check applies **whether or not** the current branch is executing. Otherwise let $s'$ be $s$ with $d$ pushed on the main stack if $\mathrm{allTrue}(s.\mathrm{vfExec})$, and $s$ unchanged otherwise. Then the **stack-size check**: failure if $1000 < |s'.\mathrm{stack}| + |s'.\mathrm{altstack}|$, else $s'$. Pushes never touch `opCount`.

**Opcode instruction $\mathrm{op}(c)$.** Let $\mathit{fExec} := \mathrm{allTrue}(s.\mathrm{vfExec})$ and $\mathit{counted} := (\mathrm{OP\_16} < c)$, i.e. $c > \mathtt{0x60}$. **Exactly the opcode bytes strictly greater than $\mathtt{0x60}$ count toward the operation limit**; $\mathrm{OP\_1NEGATE}$, $\mathrm{OP\_RESERVED}$, $\mathrm{OP\_1}$–$\mathrm{OP\_16}$ and any smaller byte do not. The steps, in order:
1. If $\mathit{counted}$ and $201 < s.\mathrm{opCount} + 1$ (equivalently $s.\mathrm{opCount} \ge 201$): failure. This runs **before** the disabled check and regardless of $\mathit{fExec}$, so opcodes inside non-executed branches are counted and can trigger the failure. The $201$st counted opcode is permitted (count becomes $201$); the $202$nd fails.
2. If $\mathit{counted}$, increment `opCount` by one.
3. If $\mathrm{isDisabled}(c)$: failure, regardless of $\mathit{fExec}$.
4. If $\mathit{fExec}$, **or** $\mathrm{OP\_IF} \le c \le \mathrm{OP\_ENDIF}$ (bytes $\mathtt{0x63}$–$\mathtt{0x68}$, which include the unnamed bytes $\mathtt{0x65}$ and $\mathtt{0x66}$): call $\mathrm{execOp}(f,o,\mathit{fExec},c,s)$ on the count-updated state; failure propagates; on success $s'$, the stack-size check $1000 < |s'.\mathrm{stack}| + |s'.\mathrm{altstack}| \Rightarrow$ failure, else $s'$. Consequently $\mathtt{0x65}$ and $\mathtt{0x66}$ fail even in a non-executed branch (they reach the catch-all), whereas $\mathtt{0x62}$, $\mathtt{0x50}$, $\mathtt{0x89}$, $\mathtt{0x8a}$ and bytes $\ge \mathtt{0xba}$ fail only when executed.
5. Otherwise (not executing, not a conditional): the stack-size check is applied to the count-updated state $s$ and $s$ is returned.

**When the stack-size check runs.** After every instruction without exception: after each push (executed or not), after each executed or conditional opcode (on the result of `execOp`), and after each skipped opcode (on the unchanged stacks). It is never run before an instruction, and it is a strict comparison against $1000$ of the sum of the two stack lengths.

## `run`, `evalScript`, `verifyScriptPlain`

**`run`**$(f, o, s, \mathit{script})$: on the empty script, returns $s$ if $s.\mathrm{vfExec}$ is empty, else failure (unbalanced conditional); on $i :: \mathit{rest}$, applies `step` to $i$ and, if that succeeds, continues with the rest. Every instruction is processed; there is no early exit other than failure.

**`evalScript`**$(f, o, \mathit{stack}, \mathit{script})$: runs the script from $\mathrm{State.initial}(\mathit{stack})$ — so with empty alt stack, empty condition stack and `opCount` $= 0$ — and returns only the final main stack (optional). The alt stack, condition stack and count are discarded.

**`verifyScriptPlain`**$(f, o, \mathit{scriptSig}, \mathit{scriptPubKey})$ (Boolean): evaluate $\mathit{scriptSig}$ from the empty stack; failure $\Rightarrow$ false. Otherwise evaluate $\mathit{scriptPubKey}$ from the resulting stack **in a fresh state** (count reset to $0$, alt stack empty); failure $\Rightarrow$ false; empty final stack $\Rightarrow$ false; otherwise the result is $\mathrm{castToBool}$ of the top element. Nothing is required of the elements below the top, of the form of $\mathit{scriptSig}$ (it may contain arbitrary opcodes), and no pay-to-script-hash or witness processing exists.

**`p2pkhScript`**$(h) = [\mathrm{op}\,\mathrm{OP\_DUP},\ \mathrm{op}\,\mathrm{OP\_HASH160},\ \mathrm{push}(h),\ \mathrm{op}\,\mathrm{OP\_EQUALVERIFY},\ \mathrm{op}\,\mathrm{OP\_CHECKSIG}]$ for any byte list $h$ (no length constraint). **`p2pkScript`**$(\mathit{pubkey}) = [\mathrm{push}(\mathit{pubkey}),\ \mathrm{op}\,\mathrm{OP\_CHECKSIG}]$.

**`opsIn`** (script $\to$ natural number): the number of $\mathrm{op}(c)$ instructions with $\mathrm{OP\_16} < c$; pushes and opcodes $\le \mathtt{0x60}$ contribute $0$. This is the static count of instructions that `step` marks as *counted*; it does not include the extra `opCount` increments that CHECKMULTISIG adds at run time.

## Features a reader may find unusual (stated, not judged)

- `castToBool` singles out a final $\mathtt{0x80}$ only when all preceding bytes are zero; $[\mathtt{0x80}, \mathtt{0x00}]$ is true.
- `toNum`'s length test is $\mathrm{maxSize} < |v|$ (a list of exactly `maxSize` bytes passes); its non-emptiness conjunct is redundant.
- The operation-count test in `step` is $201 < \mathrm{opCount} + 1$, performed before the disabled-opcode test and independent of whether the branch executes; `opsIn` counts the same opcodes statically.
- The push-size test ($520 < |d|$) in `step` applies even to pushes in skipped branches; the stack-size test runs after every instruction, including skipped ones.
- `execOp` ignores $\mathit{fExec}$ except in the IF/NOTIF branch; its correctness as a "skip" relies on `step` only calling it when executing or when $c \in [\mathtt{0x63}, \mathtt{0x68}]$. The unnamed bytes $\mathtt{0x65}$, $\mathtt{0x66}$ are in that range and hit the catch-all failure.
- In the binary arithmetic branch, $n_1$ comes from the **second** element and $n_2$ from the **top**; SUB computes $n_1 - n_2$, LESSTHAN tests $n_1 < n_2$, and WITHIN tests $n_2 \le n_1 < n_3$ with $n_1$ third from the top.
- CHECKSIG takes the public key from the **top** and the signature from the **second** element and calls $\mathrm{checkSig}(\mathit{sig}, \mathit{pubkey})$ in that argument order; the oracle receives no script-code or hash-type context.
- CLTV and CSV never pop their operand and parse it with a 5-byte limit; CSV returns success without consulting the oracle when bit $2^{31}$ is set.
- OP_SIZE and OP_DEPTH push a `serialize`d count; results of hash and arithmetic operations are never size-checked.
- `verifyScriptPlain` restarts the operation count and alt stack between the two scripts but carries the main stack across, and does not require the final stack to have exactly one element.
- `multisigLoop` has a clause ($\mathit{sigs}$ non-empty, $\mathit{keys}$ empty $\mapsto$ false) that `execOp` never reaches because it enforces $n_S \le n_K$ first.
