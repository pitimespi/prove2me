# Read-back: `BitcoinTapSoundnessV2.script_path_soundness`

**Binders and hypotheses.** For every tree $T$ of type $\mathrm{TapTree}$ (built from $\mathrm{leaf}(v', s')$, $v'$ a byte and $s'$ a byte string, and $\mathrm{branch}(l, r)$), every byte string $\mathit{control}$, every natural number $k$ (including $0$), every byte $v$, and every byte string $s$, such that

- $\mathit{hc}$: $|\mathit{control}| = 33 + 32k$;
- $h$: $\mathrm{taprootMerkleRoot}(\mathit{control}, \mathrm{tapleafHash}(v, s)) = \mathrm{hash}(T)$;

**Conclusion.** at least one of the following holds (inclusive disjunction), writing $L = \mathrm{tapleafHash}(v, s)$:

1. $\mathrm{scriptPathWitness}(T, \mathit{control}, v, s) = \mathrm{none}$ and $L \in \mathrm{leaves}(T)$; or
2. there exist byte strings $x, y$ with $\mathrm{scriptPathWitness}(T, \mathit{control}, v, s) = \mathrm{some}(x, y)$ and $\mathrm{Collides}(x, y)$.

**Unfoldings.** $\mathrm{SHA256}$ is the bundle's executable SHA-256 (MD padding, 64-byte-chunk compression from the standard IV, eight big-endian words out), total on byte strings. $\mathrm{ascii}(t)$ is the UTF-8 byte list of $t$; $\mathrm{tagged}(t, m) = \mathrm{SHA256}(\mathrm{SHA256}(\mathrm{ascii}(t)) \| \mathrm{SHA256}(\mathrm{ascii}(t)) \| m)$; $\mathrm{taggedPre}(t, m) = \mathrm{SHA256}(\mathrm{ascii}(t)) \| \mathrm{SHA256}(\mathrm{ascii}(t)) \| m$. $\mathrm{Collides}(x, y)$ is $x \neq y \wedge \mathrm{SHA256}(x) = \mathrm{SHA256}(y)$.

$\mathrm{writeCompactSize}(n)$: one byte $n$ if $n < 253$; else byte $253$ + 2 little-endian bytes if $n \le \mathtt{0xffff}$; else byte $254$ + 4 LE bytes if $n \le \mathtt{0xffffffff}$; else byte $255$ + 8 LE bytes. $\mathrm{leafMsg}(v, s) = [v] \| \mathrm{writeCompactSize}(|s|) \| s$; $\mathrm{tapleafHash}(v, s) = \mathrm{tagged}(\text{"TapLeaf"}, \mathrm{leafMsg}(v, s))$. $\mathrm{lexLt}$ is Boolean strict lexicographic order on byte strings; $\mathrm{branchMsg}(a, b) = a \| b$ if $\mathrm{lexLt}(a, b)$ else $b \| a$; $\mathrm{tapbranchHash}(a, b) = \mathrm{tagged}(\text{"TapBranch"}, \mathrm{branchMsg}(a, b))$.

$\mathrm{hash}(\mathrm{leaf}(v', s')) = \mathrm{tapleafHash}(v', s')$; $\mathrm{hash}(\mathrm{branch}(l, r)) = \mathrm{tapbranchHash}(\mathrm{hash}(l), \mathrm{hash}(r))$. $\mathrm{leaves}(\mathrm{leaf}(v', s')) = [\mathrm{tapleafHash}(v', s')]$; $\mathrm{leaves}(\mathrm{branch}(l, r)) = \mathrm{leaves}(l) \| \mathrm{leaves}(r)$; $L \in \mathrm{leaves}(T)$ is membership of the 32-byte hash $L$ in that list of hashes.

$\mathrm{controlNodes}(\mathit{control})$: with $m = \lfloor(|\mathit{control}| \dot- 33)/32\rfloor$ ($\dot-$ truncated natural subtraction), the list of $m$ consecutive 32-byte chunks of $\mathit{control}$ after its first 33 bytes. Under $\mathit{hc}$ this is exactly the $k$ trailing 32-byte blocks $n_1, \dots, n_k$ (empty when $k = 0$). $\mathrm{taprootMerkleRoot}(\mathit{control}, L)$ is the left fold $h_0 = L$, $h_i = \mathrm{tapbranchHash}(h_{i-1}, n_i)$, result $h_k$; for $k = 0$ it is $L$ itself.

$\mathrm{walk}(T, \mathit{path}, h)$ returns either a tree ($\mathrm{inl}$) or a pair of byte strings ($\mathrm{inr}$): $\mathrm{walk}(T, [], h) = \mathrm{inl}(T)$; for $n :: \mathit{rest}$, let $W = \mathrm{walk}(T, \mathit{rest}, \mathrm{tapbranchHash}(h, n))$; if $W = \mathrm{inr}(c)$ return $\mathrm{inr}(c)$; if $W = \mathrm{inl}(\mathrm{leaf}(v', s'))$ return $\mathrm{inr}\big(\mathrm{taggedPre}(\text{"TapLeaf"}, \mathrm{leafMsg}(v', s')), \mathrm{taggedPre}(\text{"TapBranch"}, \mathrm{branchMsg}(h, n))\big)$; if $W = \mathrm{inl}(\mathrm{branch}(l, r))$ return $\mathrm{inl}(l)$ if $h = \mathrm{hash}(l)$, else $\mathrm{inl}(r)$ if $h = \mathrm{hash}(r)$, else $\mathrm{inr}\big(\mathrm{taggedPre}(\text{"TapBranch"}, \mathrm{branchMsg}(\mathrm{hash}(l), \mathrm{hash}(r))), \mathrm{taggedPre}(\text{"TapBranch"}, \mathrm{branchMsg}(h, n))\big)$. The tree is descended from the root while the list is read from its end; $\mathrm{walk}$ itself checks no lengths and does not check that the folded value equals $\mathrm{hash}(T)$.

$\mathrm{scriptPathWitness}(T, \mathit{control}, v, s)$ is computed from $W = \mathrm{walk}(T, \mathrm{controlNodes}(\mathit{control}), L)$: $\mathrm{inr}(c) \mapsto \mathrm{some}(c)$; $\mathrm{inl}(\mathrm{leaf}(\cdot, \cdot)) \mapsto \mathrm{none}$ (the reached leaf's version and script are not compared with $v, s$); $\mathrm{inl}(\mathrm{branch}(l, r)) \mapsto \mathrm{some}\big(\mathrm{taggedPre}(\text{"TapLeaf"}, \mathrm{leafMsg}(v, s)), \mathrm{taggedPre}(\text{"TapBranch"}, \mathrm{branchMsg}(\mathrm{hash}(l), \mathrm{hash}(r)))\big)$.

**Edge cases and what is silently included.** $k = 0$ is allowed: then $\mathit{control}$ is 33 bytes, the path is empty, $h$ reads $L = \mathrm{hash}(T)$, $\mathrm{walk}$ returns $\mathrm{inl}(T)$, and the witness is $\mathrm{none}$ if $T$ is a leaf and $\mathrm{some}(\text{leaf preimage}, \text{root-branch preimage})$ if $T$ is a branch. No upper bound on $k$ is stated. The first 33 bytes of $\mathit{control}$ (the parity/version byte and the 32-byte internal key) play no role in this statement; neither does any tweak or output key. $v$ is any byte and $s$ any byte string. Alternative 1 asserts no collision, only that the hash $L$ occurs in the list $\mathrm{leaves}(T)$ (a list of hashes, possibly with repeats). Alternative 2 asserts that the specific pair returned by $\mathrm{scriptPathWitness}$ — an explicit expression in $T$, the $n_i$, $v$ and $s$ — consists of two different byte strings with equal SHA-256. The disjunction is inclusive.
