# Read-back: `Def_BitcoinPenalty.lean` (namespace `BitcoinPenalty`)

One paragraph per definition, in file order. Throughout, a *byte string* is a finite list of 8-bit words; $\langle d\rangle$ denotes $\mathrm{pushBytes}(d)$ (the canonical data push: length byte then $d$ for $|d| < 76$, `OP_PUSHDATA1/2/4` forms otherwise) and $[n]$ denotes $\mathrm{numBytes}(n)$ (the single opcode byte $\mathtt{0x50}+n$ for $n = -1$ or $1 \le n \le 16$, otherwise $\mathrm{pushBytes}$ of the `CScriptNum` encoding of $n$, which is the single byte $\mathtt{0x00}$ for $n = 0$). The constant $\mathrm{MAX\_SCRIPT\_ELEMENT\_SIZE}$ is $520$. An *oracle* $o$ is a record of eight functions: $o.\mathrm{ripemd160}$, $o.\mathrm{sha1}$, $o.\mathrm{sha256}$, $o.\mathrm{hash160}$, $o.\mathrm{hash256}$ (byte strings to byte strings), $o.\mathrm{checkSig}$ (two byte strings to $\{\mathrm{none}, \mathrm{some\ true}, \mathrm{some\ false}\}$), $o.\mathrm{checkLockTime}$ and $o.\mathrm{checkSequence}$ (integers to booleans). A *flag triple* $f$ has booleans $f.\mathrm{cltv}$, $f.\mathrm{csv}$, $f.\mathrm{nulldummy}$.

**`CommitmentKeys`** is a structure with nine fields, no constraints: eight byte strings $\mathrm{revPk}$, $\mathrm{revHash}$, $\mathrm{localDelayedPk}$, $\mathrm{remoteKey}$, $\mathrm{localHtlcKey}$, $\mathrm{remoteHtlcKey}$, $\mathrm{fundingKeyLocal}$, $\mathrm{fundingKeyRemote}$, and one integer $\mathrm{toSelfDelay} \in \mathbb Z$. Any byte strings and any integer (negative, zero, huge) form a valid record; nothing relates $\mathrm{revHash}$ to $\mathrm{revPk}$.

**`Htlc`** is a structure with two fields, no constraints: a byte string $\mathrm{payHash}$ and an integer $\mathrm{expiry} \in \mathbb Z$.

**`WellFormed`**$(K)$, for a `CommitmentKeys` $K$, is a proposition that is the conjunction of exactly ten facts: $|K.\mathrm{revPk}| \le 520$, $|K.\mathrm{revHash}| \le 520$, $|K.\mathrm{localDelayedPk}| \le 520$, $|K.\mathrm{remoteKey}| \le 520$, $|K.\mathrm{localHtlcKey}| \le 520$, $|K.\mathrm{remoteHtlcKey}| \le 520$, $|K.\mathrm{fundingKeyLocal}| \le 520$, $|K.\mathrm{fundingKeyRemote}| \le 520$, $0 \le K.\mathrm{toSelfDelay}$, and $K.\mathrm{toSelfDelay} < 2^{16}$. It imposes nothing else (no key validity, no 20-byte hash length, no hash relation).

**`HtlcWellFormed`**$(h)$, for an `Htlc` $h$, is the conjunction of two facts: $|h.\mathrm{payHash}| \le 520$ and $|h.\mathrm{expiry}| < 2^{32}$ (the absolute value of the integer; $h.\mathrm{expiry}$ may be zero or negative).

**`toLocalBytes`**$(K)$ is the byte string $\mathrm{BitcoinToLocal.toLocalBytes}(K.\mathrm{revPk}, K.\mathrm{toSelfDelay}, K.\mathrm{localDelayedPk})$, which unfolds to `OP_IF` $(\mathtt{0x63})$ $\Vert$ $\langle K.\mathrm{revPk}\rangle$ $\Vert$ `OP_ELSE` $(\mathtt{0x67})$ $\Vert$ $[K.\mathrm{toSelfDelay}]$ $\Vert$ `OP_CHECKSEQUENCEVERIFY OP_DROP` $(\mathtt{0xb2}\,\mathtt{0x75})$ $\Vert$ $\langle K.\mathrm{localDelayedPk}\rangle$ $\Vert$ `OP_ENDIF OP_CHECKSIG` $(\mathtt{0x68}\,\mathtt{0xac})$.

**`offeredBytes`**$(K, h)$ is $\mathrm{BitcoinHtlc.offeredBytes}(K.\mathrm{revHash}, K.\mathrm{remoteHtlcKey}, K.\mathrm{localHtlcKey}, h.\mathrm{payHash})$: `OP_DUP OP_HASH160` $\langle K.\mathrm{revHash}\rangle$ `OP_EQUAL OP_IF OP_CHECKSIG OP_ELSE` $\langle K.\mathrm{remoteHtlcKey}\rangle$ `OP_SWAP OP_SIZE` $[32]$ `OP_EQUAL OP_NOTIF OP_DROP` $[2]$ `OP_SWAP` $\langle K.\mathrm{localHtlcKey}\rangle$ $[2]$ `OP_CHECKMULTISIG OP_ELSE OP_HASH160` $\langle h.\mathrm{payHash}\rangle$ `OP_EQUALVERIFY OP_CHECKSIG OP_ENDIF OP_ENDIF`. (Argument order: the second key argument of the HTLC constructor, "remoteKey", receives $K.\mathrm{remoteHtlcKey}$ and the third, "localKey", receives $K.\mathrm{localHtlcKey}$.)

**`receivedBytes`**$(K, h)$ is $\mathrm{BitcoinHtlc.receivedBytes}(K.\mathrm{revHash}, K.\mathrm{remoteHtlcKey}, K.\mathrm{localHtlcKey}, h.\mathrm{payHash}, h.\mathrm{expiry})$: `OP_DUP OP_HASH160` $\langle K.\mathrm{revHash}\rangle$ `OP_EQUAL OP_IF OP_CHECKSIG OP_ELSE` $\langle K.\mathrm{remoteHtlcKey}\rangle$ `OP_SWAP OP_SIZE` $[32]$ `OP_EQUAL OP_IF OP_HASH160` $\langle h.\mathrm{payHash}\rangle$ `OP_EQUALVERIFY` $[2]$ `OP_SWAP` $\langle K.\mathrm{localHtlcKey}\rangle$ $[2]$ `OP_CHECKMULTISIG OP_ELSE OP_DROP` $[h.\mathrm{expiry}]$ `OP_CHECKLOCKTIMEVERIFY OP_DROP OP_CHECKSIG OP_ENDIF OP_ENDIF`.

**`offeredBytesAnchors`**$(K, h)$ is $\mathrm{BitcoinAnchors.offeredBytes}(K.\mathrm{revHash}, K.\mathrm{remoteHtlcKey}, K.\mathrm{localHtlcKey}, h.\mathrm{payHash})$: the same byte string as `offeredBytes`$(K,h)$ except that between the inner `OP_ENDIF` and the outer `OP_ENDIF` the bytes $[1]$ `OP_CHECKSEQUENCEVERIFY OP_DROP` ($\mathtt{0x51}\,\mathtt{0xb2}\,\mathtt{0x75}$) are inserted.

**`receivedBytesAnchors`**$(K, h)$ is $\mathrm{BitcoinAnchors.receivedBytes}(K.\mathrm{revHash}, K.\mathrm{remoteHtlcKey}, K.\mathrm{localHtlcKey}, h.\mathrm{payHash}, h.\mathrm{expiry})$: the same byte string as `receivedBytes`$(K,h)$ with $[1]$ `OP_CHECKSEQUENCEVERIFY OP_DROP` inserted between the inner and outer `OP_ENDIF`.

**`toRemoteBytes`**$(K)$ is $\mathrm{BitcoinAnchors.toRemoteBytes}(K.\mathrm{remoteKey}) = \langle K.\mathrm{remoteKey}\rangle$ $\Vert$ `OP_CHECKSIGVERIFY` $(\mathtt{0xad})$ $\Vert$ $[1]$ $(\mathtt{0x51})$ $\Vert$ `OP_CHECKSEQUENCEVERIFY` $(\mathtt{0xb2})$.

**`anchorLocalBytes`**$(K)$ is $\mathrm{BitcoinAnchors.anchorBytes}(K.\mathrm{fundingKeyLocal}) = \langle K.\mathrm{fundingKeyLocal}\rangle$ $\Vert$ `OP_CHECKSIG OP_IFDUP OP_NOTIF` $(\mathtt{0xac}\,\mathtt{0x73}\,\mathtt{0x64})$ $\Vert$ $[16]$ $(\mathtt{0x60})$ $\Vert$ `OP_CHECKSEQUENCEVERIFY OP_ENDIF` $(\mathtt{0xb2}\,\mathtt{0x68})$.

**`anchorRemoteBytes`**$(K)$ is the same construction applied to $K.\mathrm{fundingKeyRemote}$: $\langle K.\mathrm{fundingKeyRemote}\rangle$ `OP_CHECKSIG OP_IFDUP OP_NOTIF` $[16]$ `OP_CHECKSEQUENCEVERIFY OP_ENDIF`.

**`p2wshOf`**$(\mathcal S)$, for any byte string $\mathcal S$, is $\mathrm{witnessBytes}(0, \mathrm{sha256}(\mathcal S))$, i.e. the byte $\mathtt{0x00}$ followed by $\mathrm{pushBytes}(\mathrm{sha256}(\mathcal S))$, which is $\mathtt{0x00}\,\mathtt{0x20}$ followed by the 32 bytes of $\mathrm{BitcoinSer.sha256}(\mathcal S)$ — the concrete SHA-256 transcribed in the serialization file. No constraint on $\mathcal S$ (it need not be a parseable script).

**`oracleOf`**$(c, \mathcal S)$, for a verification context $c$ (flags $c.\mathrm{flags}$, transaction $c.tx$, input index $c.\mathrm{nIn} \in \mathbb N$, amount $c.\mathrm{amount} \in \mathbb Z$) and a byte string $\mathcal S$, is the oracle $\mathrm{legacyOracle}(\mathrm{sigFlagsOf}(c.\mathrm{flags}), c.tx, c.\mathrm{nIn}, c.\mathrm{amount}, \mathrm{witnessV0}, \mathcal S)$, whose components are: the concrete $\mathrm{ripemd160}$, $\mathrm{sha1}$, $\mathrm{sha256}$, $\mathrm{hash160} = \mathrm{ripemd160}\circ\mathrm{sha256}$, $\mathrm{hash256} = \mathrm{sha256}\circ\mathrm{sha256}$ of the serialization file; $\mathrm{checkSig}(sig, pk) = \mathrm{checkSigPreTapscript}((\mathrm{dersig} = c.\mathrm{flags}.\mathrm{dersig}, \mathrm{lowS} = \mathrm{false}, \mathrm{strictenc} = \mathrm{false}, \mathrm{witnessPubkeyType} = \mathrm{false}), c.tx, c.\mathrm{nIn}, c.\mathrm{amount}, \mathrm{witnessV0}, \mathcal S, sig, pk)$, which is $\mathrm{none}$ iff $c.\mathrm{flags}.\mathrm{dersig} = \mathrm{true}$ and $sig$ is non-empty and fails `IsValidSignatureEncoding`, and otherwise $\mathrm{some}$ of the BIP143 ECDSA verdict (public key header/length check, non-empty signature whose last byte is the hash type, $c.\mathrm{amount} \ge 0$, lax-DER parse, low-$s$ normalization, secp256k1 verification against the signature hash of $c.tx$ at input $c.\mathrm{nIn}$ — the default empty input if out of range — with script code $\mathcal S$ and amount $c.\mathrm{amount}$); $\mathrm{checkLockTime}(L) = \mathrm{checkLockTime}(c.tx, c.\mathrm{nIn}, L)$ ($c.tx.\mathrm{nLockTime}$ and $L$ on the same side of $500000000$, $L \le c.tx.\mathrm{nLockTime}$, input $c.\mathrm{nIn}$'s sequence $\ne \mathtt{0xffffffff}$); and $\mathrm{checkSequence}(S) = \mathrm{checkSequence}(c.tx, c.\mathrm{nIn}, S)$ ($c.tx.\mathrm{version} \ge 2$, input $c.\mathrm{nIn}$'s sequence $\sigma$ has bit 31 clear, $\sigma \mathbin{\&} (2^{22} \mathbin{|} \mathtt{0xffff})$ and $\max(S,0) \mathbin{\&} (2^{22} \mathbin{|} \mathtt{0xffff})$ on the same side of $2^{22}$, and the latter $\le$ the former).

**`HoldsRevocation`**$(o, K)$, for an oracle $o$ and keys $K$, is the conjunction of (i) there exists a byte string $sig_R$ with $|sig_R| \le 520$ and $o.\mathrm{checkSig}(sig_R, K.\mathrm{revPk}) = \mathrm{some\ true}$, and (ii) $o.\mathrm{hash160}(K.\mathrm{revPk}) = K.\mathrm{revHash}$. It is stated for an abstract oracle; nothing ties $o$ to any transaction unless $o$ is instantiated (e.g. by `oracleOf`).

**`NoRevocationSig`**$(o, K)$ is: for every byte string $sig$, $o.\mathrm{checkSig}(sig, K.\mathrm{revPk}) \ne \mathrm{some\ true}$ (each answer is $\mathrm{none}$ or $\mathrm{some\ false}$). It says nothing about other keys and nothing about $K.\mathrm{revHash}$.

**`NoRevHashPreimage`**$(o, K)$ is: for every byte string $pk$, if $o.\mathrm{hash160}(pk) = K.\mathrm{revHash}$ then $pk = K.\mathrm{revPk}$. It does not assert that $K.\mathrm{revPk}$ itself hashes to $K.\mathrm{revHash}$; it holds vacuously when no byte string hashes to $K.\mathrm{revHash}$.

**`toLocalPenaltyWitness`**$(K, sig_R)$ is the three-element list of byte strings $[\,sig_R,\ [\mathtt{0x01}],\ \mathrm{toLocalBytes}(K)\,]$, in `CScriptWitness` order (last element on top of the stack, the script last): when executed, the stack top-first is $[[\mathtt{0x01}], sig_R]$.

**`htlcPenaltyWitness`**$(K, sig_R, \mathcal S)$ is the three-element list $[\,sig_R,\ K.\mathrm{revPk},\ \mathcal S\,]$ for an arbitrary byte string $\mathcal S$ (not required to be one of the HTLC scripts); when executed, the stack top-first is $[K.\mathrm{revPk}, sig_R]$.

**`DelayedSpend`**$(f, o, K, b, sig)$, for a flag triple $f$, oracle $o$, keys $K$ and byte strings $b$, $sig$, is the conjunction of three facts: $\mathrm{castToBool}(b) = \mathrm{false}$ ($b$ is empty, all zero bytes, or zero bytes ending in $\mathtt{0x80}$); $\mathrm{CsvPasses}(f, o, K.\mathrm{toSelfDelay})$, i.e. $f.\mathrm{csv} = \mathrm{false}$ or ($0 \le K.\mathrm{toSelfDelay}$ and ($\max(K.\mathrm{toSelfDelay},0) \mathbin{\&} 2^{31} \ne 0$ or $o.\mathrm{checkSequence}(K.\mathrm{toSelfDelay}) = \mathrm{true}$)); and $o.\mathrm{checkSig}(sig, K.\mathrm{localDelayedPk}) = \mathrm{some\ true}$.

**`OfferedNonRevocation`**$(f, o, K, h, st)$, for a top-first stack $st$ (list of byte strings), is the disjunction of two existential statements. **First disjunct:** there exist byte strings $\mathrm{pre}$, $sig$ with $st = [\mathrm{pre}, sig]$, $o.\mathrm{hash160}(\mathrm{pre}) \ne K.\mathrm{revHash}$, $|\mathrm{pre}| = 32$, $o.\mathrm{hash160}(\mathrm{pre}) = h.\mathrm{payHash}$, and $o.\mathrm{checkSig}(sig, K.\mathrm{remoteHtlcKey}) = \mathrm{some\ true}$. **Second disjunct:** there exist byte strings $x$, $sig_L$, $sig_R'$, $\mathrm{dummy}$ with $st = [x, sig_L, sig_R', \mathrm{dummy}]$, $o.\mathrm{hash160}(x) \ne K.\mathrm{revHash}$, $|x| \ne 32$, $\mathrm{multisigLoop}(o, [sig_L, sig_R'], [K.\mathrm{localHtlcKey}, K.\mathrm{remoteHtlcKey}]) = \mathrm{some\ true}$ (which, by the loop's definition on two signatures and two keys, holds iff $o.\mathrm{checkSig}(sig_L, K.\mathrm{localHtlcKey}) = \mathrm{some\ true}$ and $o.\mathrm{checkSig}(sig_R', K.\mathrm{remoteHtlcKey}) = \mathrm{some\ true}$), and $f.\mathrm{nulldummy} = \mathrm{true} \Rightarrow \mathrm{dummy} = [\,]$. There is no revocation disjunct.

**`ReceivedNonRevocation`**$(f, o, K, h, st)$ is the disjunction of two existential statements. **First disjunct:** there exist $\mathrm{pre}$, $sig_L$, $sig_R'$, $\mathrm{dummy}$ with $st = [\mathrm{pre}, sig_L, sig_R', \mathrm{dummy}]$, $o.\mathrm{hash160}(\mathrm{pre}) \ne K.\mathrm{revHash}$, $|\mathrm{pre}| = 32$, $o.\mathrm{hash160}(\mathrm{pre}) = h.\mathrm{payHash}$, $\mathrm{multisigLoop}(o, [sig_L, sig_R'], [K.\mathrm{localHtlcKey}, K.\mathrm{remoteHtlcKey}]) = \mathrm{some\ true}$ (iff both signatures verify for their respective keys with answer $\mathrm{some\ true}$), and $f.\mathrm{nulldummy} = \mathrm{true} \Rightarrow \mathrm{dummy} = [\,]$. **Second disjunct:** there exist $x$, $sig$ with $st = [x, sig]$, $o.\mathrm{hash160}(x) \ne K.\mathrm{revHash}$, $|x| \ne 32$, $\mathrm{BitcoinHtlc.CltvPasses}(f, o, h.\mathrm{expiry})$ — i.e. $f.\mathrm{cltv} = \mathrm{false}$ or ($0 \le h.\mathrm{expiry}$ and $o.\mathrm{checkLockTime}(h.\mathrm{expiry}) = \mathrm{true}$) — and $o.\mathrm{checkSig}(sig, K.\mathrm{remoteHtlcKey}) = \mathrm{some\ true}$. There is no revocation disjunct.

**`OfferedNonRevocationAnchors`**$(f, o, K, h, st)$ is the conjunction $\mathrm{OfferedNonRevocation}(f, o, K, h, st) \land \mathrm{CsvPasses}(f, o, 1)$, where $\mathrm{CsvPasses}(f, o, 1)$ unfolds to $f.\mathrm{csv} = \mathrm{false} \lor (0 \le 1 \land (1 \mathbin{\&} 2^{31} \ne 0 \lor o.\mathrm{checkSequence}(1) = \mathrm{true}))$, i.e. $f.\mathrm{csv} = \mathrm{false} \lor o.\mathrm{checkSequence}(1) = \mathrm{true}$. The CSV conjunct is outside the disjunction, so it is required on both paths.

**`ReceivedNonRevocationAnchors`**$(f, o, K, h, st)$ is the conjunction $\mathrm{ReceivedNonRevocation}(f, o, K, h, st) \land \mathrm{CsvPasses}(f, o, 1)$, with $\mathrm{CsvPasses}(f, o, 1)$ as just unfolded; again required on both paths.
