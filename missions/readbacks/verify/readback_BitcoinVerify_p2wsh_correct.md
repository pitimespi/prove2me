# Read-back: `BitcoinVerify.p2wsh_correct`

**Binders and hypothesis.** Universally quantified: `tap`, a Taproot handler (any function from a context, a list of byte strings and a byte string to a Boolean); $c$, a verification context (consensus flags `c.flags`, transaction `c.tx`, input index `c.nIn`, integer amount `c.amount`); `ws`, a list of byte strings; `script`, a byte string. One hypothesis `hf`: `c.flags.witness = true`. There are no size hypotheses on `ws`, its elements, or `script`.

**Conclusion.** Let $P = \mathrm{sha256}(\mathrm{script})$ (32 bytes) and $\pi = \mathrm{witnessBytes}(0, P) = \mathtt{0x00}\ \mathtt{0x20}\ P$ (34 bytes). Then
$$\mathrm{verifyScript}(\mathrm{tap}, c, [], \pi, \mathrm{ws} \,\|\, [\mathrm{script}]) = \mathrm{true} \iff \mathrm{castToBool}(P) = \mathrm{true} \ \wedge\ \mathrm{executeWitnessScriptV0}(c, \mathrm{reverse}(\mathrm{ws}), \mathrm{script}) = \mathrm{true}.$$
The witness is the list `ws` with `script` appended as its last element.

**Unfolding the left-hand side.** The empty scriptSig evaluates to the empty stack. $\pi$ evaluates (version `base`) to the top-first stack $[P, []]$ (the byte $\mathtt{0x00}$ pushes the empty string, then the 32-byte push). `topTrue` is $\mathrm{castToBool}(P)$: if the SHA-256 digest is all zeros or zeros followed by a final $\mathtt{0x80}$, `verifyScript` returns false. Otherwise, with the `witness` flag on (`hf`), `isWitnessProgram π` $= \mathrm{some}(0, P)$ (length $34 \in [4, 42]$, first byte $0$, second byte $32 = 34 - 2$), and the scriptSig is empty, so `verifyScript` returns exactly `verifyWitnessProgram tap c (ws ++ [script]) 0 P false`.

**Unfolding `verifyWitnessProgram`.** Version $0$, $|P| = 32$ (the script-hash size): the last element of the witness, `getLast? (ws ++ [script])`, is `script` (the witness is non-empty by construction); the test $\mathrm{sha256}(\mathrm{script}) \ne P$ fails to trigger since $P$ is defined as that hash; so the result is `executeWitnessScriptV0 c ((ws ++ [script]).dropLast.reverse) script` $=$ `executeWitnessScriptV0 c (reverse ws) script`. The witness elements other than the script are reversed, so the element of `ws` that was last in serialized order becomes the interpreter's top.

**Unfolding `executeWitnessScriptV0` (the right-hand side).** `executeWitnessScriptV0 c (reverse ws) script` is: false if some element of `ws` is longer than 520 bytes; otherwise `evalBytes c witnessV0 (reverse ws) script` — false if $|\mathrm{script}| > 10000$, false if `script` fails the byte-level parse, false if the interpreter (flags `scriptFlagsOf c.flags`; oracle with signature check `checkSigPreTapscript (sigFlagsOf c.flags) c.tx c.nIn c.amount witnessV0 script`, script code the whole `script`) fails; otherwise true iff the final stack has **exactly one** element and that element casts to true. The `script` element itself is not subject to the 520-byte test (it was removed by `dropLast`), only to the $10000$-byte test.

**Logical content.** For every handler, context with the witness flag on, witness prefix `ws` and script, the full verification of an empty scriptSig against the native version-0 32-byte program equals the conjunction of (i) the program bytes casting to true and (ii) the witness-script execution verdict on the reversed remaining witness. Both directions are asserted.

**What is not said.** Nothing when the `witness` flag is off; nothing for a non-empty scriptSig; nothing about witnesses whose last element does *not* hash to the program (the statement fixes the program as the hash of the last element); nothing about P2SH-wrapped P2WSH; no size constraints are asserted — they are absorbed into `executeWitnessScriptV0` on the right; no clean-stack condition beyond the one-element rule inside `executeWitnessScriptV0`; the handler `tap`, the `taproot` and `p2sh` flags are not consulted on this path and the theorem is silent about them. It does not unfold what the interpreter does with `script`.
