# Read-back: `BitcoinVerify.p2sh_p2wpkh_correct`

**Binders and hypothesis.** Universally quantified: `tap`, a Taproot handler (an arbitrary function from a context, a list of byte strings and a byte string to a Boolean); $c$, a verification context with consensus flags `c.flags`, transaction `c.tx`, input index `c.nIn`, integer amount `c.amount`; `sig`, `pk`, $h$, byte strings. Five hypotheses:

- `hp`: `c.flags.p2sh = true`;
- `hf`: `c.flags.witness = true`;
- `hh`: $|h| = 20$;
- `hsig`: $|\mathrm{sig}| \le 520$;
- `hpk`: $|\mathrm{pk}| \le 520$.

**Conclusion.** Let $r = \mathrm{witnessBytes}(0, h) = \mathtt{0x00}\ \mathtt{0x14}\ h$ (the 22-byte redeem script), $\sigma = \mathrm{pushBytes}(r) = \mathtt{0x16}\ r$ (23 bytes), and $\pi = \mathrm{p2shBytes}(\mathrm{hash160}(r)) = \mathtt{0xa9}\ \mathtt{0x14}\ \mathrm{hash160}(r)\ \mathtt{0x87}$ (23 bytes, since `hash160` yields 20 bytes). Then
$$\mathrm{verifyScript}(\mathrm{tap}, c, \sigma, \pi, [\mathrm{sig}, \mathrm{pk}]) = \mathrm{true} \iff \mathrm{castToBool}(h) = \mathrm{true} \ \wedge\ \mathrm{hash160}(\mathrm{pk}) = h \ \wedge\ \mathrm{checkSigPreTapscript}(F, c.\mathrm{tx}, c.\mathrm{nIn}, c.\mathrm{amount}, \mathrm{witnessV0}, \mathrm{p2pkhBytes}(h), \mathrm{sig}, \mathrm{pk}) = \mathrm{some}(\mathrm{true}),$$
with $F = \mathrm{sigFlagsOf}(c.\mathrm{flags}) = \langle c.\mathrm{flags.dersig}, \mathrm{false}, \mathrm{false}, \mathrm{false}\rangle$ and $\mathrm{p2pkhBytes}(h) = \mathtt{0x76}\ \mathtt{0xa9}\ \mathtt{0x14}\ h\ \mathtt{0x88}\ \mathtt{0xac}$.

**Unfolding the left-hand side, outer evaluations.** $\sigma$ evaluated on the empty stack (version `base`) is a single push of $r$: `stackSig` $= [r]$. Then $\pi$ on $[r]$: `OP_HASH160` → $[\mathrm{hash160}(r)]$; push → $[\mathrm{hash160}(r), \mathrm{hash160}(r)]$; `OP_EQUAL` → $[[\mathtt{0x01}]]$; `topTrue` is true. The native branch: `isWitnessProgram π` is nothing ($\pi$ starts with $\mathtt{0xa9}$), so `native = none`. With `hp` and `isPayToScriptHash π` true, the P2SH branch runs. `isPushOnly σ` holds (one canonical push). `stackSig` is $r :: []$, so `redeem` $= r$ and the remainder is the empty stack. Then `evalBytes c base [] r` runs: $r$ parses as a push of the empty string and a push of $h$, giving `stack2` $= [h, []]$ with `topTrue` $= \mathrm{castToBool}(h)$ — false (and the verification false) if $h$ is twenty zero bytes or nineteen zero bytes followed by $\mathtt{0x80}$. Next, since `c.flags.witness` is true (`hf`), `isWitnessProgram r` is $\mathrm{some}(0, h)$ (length 22, first byte 0, second byte 20); the check $\sigma = \mathrm{pushBytes}(r)$ holds by construction; the verdict is `verifyWitnessProgram tap c [sig, pk] 0 h true`.

**Unfolding `verifyWitnessProgram` and `executeWitnessScriptV0`.** Version $0$, $|h| = 20$: the witness must have exactly two elements (it does), and the result is `executeWitnessScriptV0 c [pk, sig] (p2pkhBytes h)` — the witness list **reversed**, `pk` on top. The `isP2sh = true` argument plays no role in the version-0 arm. `executeWitnessScriptV0` requires every stack element at most 520 bytes (`hsig`, `hpk`), then runs `evalBytes c witnessV0 [pk, sig] (p2pkhBytes h)`: `OP_DUP`, `OP_HASH160`, push $h$, `OP_EQUALVERIFY` (fails unless $\mathrm{hash160}(\mathrm{pk}) = h$, leaving $[\mathrm{pk}, \mathrm{sig}]$), then `OP_CHECKSIG` pops `pk` (pubkey) and `sig` and consults the oracle `checkSigPreTapscript F c.tx c.nIn c.amount witnessV0 (p2pkhBytes h) sig pk`: "nothing" fails the script (an encoding check failed — only `dersig` can be on), `some ok` pushes $[\mathtt{0x01}]$ or the empty string. Exactly one element remains and the verdict is `ok`. So the left side is true iff $\mathrm{castToBool}(h)$, $\mathrm{hash160}(\mathrm{pk}) = h$ and the oracle returns `some true`, i.e. the right side. Under version `witnessV0` the script code is `p2pkhBytes h` unaltered; the ECDSA check uses the digest with `c.amount` and is false when `c.amount < 0`.

**What is not said.** Nothing for a scriptSig other than exactly the canonical push of $r$ (any other encoding of the same push, or extra pushes, is outside the statement); nothing for a witness other than exactly `[sig, pk]`; nothing when either the `p2sh` or `witness` flag is off; nothing when $|h| \ne 20$ or elements exceed 520 bytes. `checkSigPreTapscript` is left unexpanded on the right — the theorem does not spell out the signature-hash or the elliptic-curve verification. The handler `tap` and the `taproot` flag are never consulted on this path and the theorem says nothing about them. The theorem does not say that the two sides are *both* true, only that they are equivalent.
