# Read-back: `BitcoinSer.block_roundtrip`

**Binders and hypothesis.** A Boolean $aw$ (either value), a block record $b$ (a header and a list $b.\texttt{vtx}$ of transactions), a byte string $\texttt{rest}$ (arbitrary), and the hypothesis $hw : b.\texttt{wf}$, which unfolds to:

- $b.\texttt{header}$ is well-formed: $-2^{31} \le \texttt{version} < 2^{31}$, $|\texttt{prevBlock}| = 32$, $|\texttt{merkleRoot}| = 32$, $\texttt{time}, \texttt{bits}, \texttt{nonce} < 2^{32}$;
- $|b.\texttt{vtx}| \le \texttt{MAX\_SIZE}$ (with $\texttt{MAX\_SIZE} = 2^{25}$, equality allowed);
- for every $tx$ in $b.\texttt{vtx}$: $tx.\texttt{wf}$ (version and lock time $< 2^{32}$; input and output counts $\le \texttt{MAX\_SIZE}$; each input has a 32-byte outpoint hash, index and sequence $< 2^{32}$, script length $\le \texttt{MAX\_SIZE}$, at most $\texttt{MAX\_SIZE}$ witness items each of length $\le \texttt{MAX\_SIZE}$; each output has value in $[-2^{63}, 2^{63})$ and script length $\le \texttt{MAX\_SIZE}$) **and** ($tx.\texttt{vin} \ne [\,]$ or $\texttt{hasWitness}(tx) = \mathrm{true}$). The second disjunct implies the first (a non-empty witness lives on some input), so this says every transaction in the block has at least one input — and this is demanded for both values of $aw$.

**Conclusion.**
$$\texttt{readBlock}\;aw\;\big(\texttt{serBlock}\;aw\;b \mathbin{+\!\!+} \texttt{rest}\big) = \mathrm{some}\,\Big(\big\langle b.\texttt{header},\ \texttt{map}\;(tx \mapsto \text{if } aw \text{ then } tx \text{ else } \texttt{stripWitness}\;tx)\;b.\texttt{vtx}\big\rangle,\ \texttt{rest}\Big).$$
Parsing in mode $aw$ the mode-$aw$ serialization of $b$, followed by arbitrary bytes, succeeds; the parsed header equals $b$'s header exactly; the parsed transaction list has the same length and order as $b.\texttt{vtx}$, with the $i$-th parsed transaction equal to the $i$-th original when $aw$ is true and to its witness-stripped copy (all witness lists emptied, everything else unchanged) when $aw$ is false; and the remainder is exactly $\texttt{rest}$. When $aw$ is true the right side is $\mathrm{some}\,(b, \texttt{rest})$ up to the trivial identity map.

**Unfolding.** $\texttt{serBlock}\;aw\;b = \texttt{serHeader}(b.\texttt{header}) \mathbin{+\!\!+} \texttt{writeCompactSize}(|b.\texttt{vtx}|) \mathbin{+\!\!+} \texttt{serTx}\;aw\;tx_1 \mathbin{+\!\!+} \cdots \mathbin{+\!\!+} \texttt{serTx}\;aw\;tx_n$. $\texttt{readBlock}\;aw$ parses an 80-byte header (signed version, two 32-byte hashes, three unsigned 4-byte fields), then a range-checked CompactSize count, then exactly that many transactions with $\texttt{readTx}\;aw$, each consuming its own bytes and handing the remainder to the next. Each $\texttt{readTx}\;aw$ behaves as described for `tx_roundtrip`: in mode false it ignores the flags logic and returns inputs with empty witnesses; in mode true it reads the marker $[0,1]$ and the witness stacks when the transaction has a witness, and takes the direct path when the input list is non-empty. The per-transaction "at least one input" condition plays the role of $hv$ in `tx_roundtrip` for each transaction when $aw$ is true (it is assumed but unused when $aw$ is false). The header $\texttt{wf}$ bounds make the header parse exact, and $|b.\texttt{vtx}| \le \texttt{MAX\_SIZE}$ makes the range-checked count readable. The degenerate block with $b.\texttt{vtx} = [\,]$ is included: the count byte $0$ is read and zero transactions follow.

**What is not said.** Nothing about blocks violating $\texttt{wf}$, in particular blocks containing a transaction with no inputs — even in mode false, where such a block would in fact parse, the theorem makes no claim. No converse: nothing says a parsed block is well-formed or arose from $\texttt{serBlock}$. Nothing about mixed modes (serialize with one $aw$, parse with the other). Nothing about $\texttt{headerHash}$, $\texttt{blockWeight}$, $\texttt{MAX\_BLOCK\_WEIGHT}$, merkle roots (the header's merkle-root field is parsed as 32 opaque bytes; no relation to $b.\texttt{vtx}$ is assumed or concluded), or lengths. It is the one-directional parse-after-serialize statement for blocks, per mode, under $\texttt{wf}$.
