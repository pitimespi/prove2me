# Read-back: `BitcoinSer.serBlock_injective`

**Binders and hypothesis.** Two block records $b_1, b_2$ (each a header plus a list of transactions) and three hypotheses:

- $h_1 : b_1.\texttt{wf}$ and $h_2 : b_2.\texttt{wf}$. For a block $b$, $\texttt{wf}$ unfolds to: the header is well-formed ($-2^{31} \le \texttt{version} < 2^{31}$, both hash fields of length exactly 32, time/bits/nonce $< 2^{32}$); $|b.\texttt{vtx}| \le \texttt{MAX\_SIZE}$; and for every transaction $tx$ in $b.\texttt{vtx}$, both $tx.\texttt{wf}$ (version and lock time $< 2^{32}$, input and output counts $\le \texttt{MAX\_SIZE}$, every input with a 32-byte outpoint hash, index and sequence $< 2^{32}$, script and witness-count and each witness item of length $\le \texttt{MAX\_SIZE}$; every output with value in $[-2^{63}, 2^{63})$ and script of length $\le \texttt{MAX\_SIZE}$) **and** ($tx.\texttt{vin} \ne [\,]$ or $\texttt{hasWitness}(tx) = \mathrm{true}$). Since a non-empty witness requires an input, the parenthesised condition is equivalent to "$tx$ has at least one input".
- $h : \texttt{serBlock}\;\mathrm{true}\;b_1 = \texttt{serBlock}\;\mathrm{true}\;b_2$: the witness-mode serializations are the same byte string.

**Conclusion.** $b_1 = b_2$ — equality of records, hence equality of headers field by field and equality of the transaction lists element by element, including every input's witness list, every output's integer value, and so on.

**Unfolding.** $\texttt{serBlock}\;\mathrm{true}\;b = \texttt{serHeader}(b.\texttt{header}) \mathbin{+\!\!+} \texttt{writeCompactSize}(|b.\texttt{vtx}|) \mathbin{+\!\!+} \bigl(\text{concatenation of } \texttt{serTx}\;\mathrm{true}\;tx \text{ over } tx \in b.\texttt{vtx}\bigr)$. The header part is the 80-byte string (signed 4-byte version, 32 + 32 raw hash bytes, three 4-byte fields). Each $\texttt{serTx}\;\mathrm{true}\;tx$ includes the marker $[0,1]$ and the witness stacks exactly when $tx$ has a non-empty witness, and omits both otherwise. The statement asserts that, within the class of well-formed blocks, this encoding is injective: no two distinct well-formed blocks share a witness-mode serialization. The $\texttt{wf}$ conditions are what make the fixed-width and raw-hash fields unambiguous (no truncation, hash fields of known length), the counts canonical and within range, and the signed values recoverable; the "at least one input" condition is what distinguishes the marker $[0, 1]$ (an empty input count followed by flags) from a genuine transaction with zero inputs, so that the witness-mode encoding can be decoded unambiguously. Note that the mode is fixed to `true` on both sides; witness data is therefore part of the compared bytes, and distinct witnesses yield distinct serializations.

**What is not said.** Nothing about $\texttt{serBlock}\;\mathrm{false}$, which discards witnesses and is not injective on blocks that differ only in witnesses — no claim is made either way. Nothing about blocks that are not well-formed: two non-well-formed blocks (e.g. with a 31-byte and a 33-byte previous-hash field arranged to produce the same bytes, or values differing by a multiple of $2^{32}$) could serialize identically, and the theorem is silent. The theorem is not a round-trip statement: it does not say $\texttt{readBlock}$ recovers $b$ (that is `block_roundtrip`), nor does it mention hashes, weights, or lengths. It does not say the map is surjective onto any set of byte strings. It is a single implication: equal witness-mode serializations of two well-formed blocks force equal blocks.
