# Read-back: `BitcoinSer.tx_roundtrip`

**Binders and hypothesis.** A Boolean $aw$ ("allow witness", either value), a transaction record $tx$, a byte string $\texttt{rest}$ (arbitrary), and two hypotheses:

- $hw : tx.\texttt{wf}$, which unfolds to: $tx.\texttt{version} < 2^{32}$; $tx.\texttt{nLockTime} < 2^{32}$; $|tx.\texttt{vin}| \le \texttt{MAX\_SIZE}$; $|tx.\texttt{vout}| \le \texttt{MAX\_SIZE}$; every input $i$ satisfies $|i.\texttt{prevout.hash}| = 32$, $i.\texttt{prevout.n} < 2^{32}$, $|i.\texttt{scriptSig}| \le \texttt{MAX\_SIZE}$, $i.\texttt{nSequence} < 2^{32}$, $|i.\texttt{witness}| \le \texttt{MAX\_SIZE}$ and every witness item has length $\le \texttt{MAX\_SIZE}$; every output $o$ satisfies $-2^{63} \le o.\texttt{nValue} < 2^{63}$ and $|o.\texttt{scriptPubKey}| \le \texttt{MAX\_SIZE}$. Here $\texttt{MAX\_SIZE} = 2^{25}$ and all bounds on lengths are non-strict.
- $hv : aw = \mathrm{true} \Rightarrow tx.\texttt{vin} \ne [\,]$: if witness mode is on, the transaction has at least one input. When $aw$ is false this hypothesis is vacuous and $tx$ may have no inputs.

**Conclusion.**
$$\texttt{readTx}\;aw\;\big(\texttt{serTx}\;aw\;tx \mathbin{+\!\!+} \texttt{rest}\big) = \mathrm{some}\,\big(\,(\text{if } aw \text{ then } tx \text{ else } \texttt{stripWitness}\;tx),\ \texttt{rest}\,\big).$$
That is: parsing, in mode $aw$, the mode-$aw$ serialization of $tx$ followed by arbitrary trailing bytes succeeds; the parsed record equals $tx$ itself when $aw$ is true and equals $tx$ with all witness lists emptied when $aw$ is false; and the remainder is exactly $\texttt{rest}$.

**Unfolding the serializer.** Let $\phi = 1$ if $aw$ and $\texttt{hasWitness}(tx)$ (some input has a non-empty witness), else $0$. $\texttt{serTx}\;aw\;tx$ is the 4-byte little-endian version, then $[0, 1]$ if $\phi = 1$, then the CompactSize count of inputs and each input (32 raw hash bytes, 4-byte index, CompactSize-prefixed script, 4-byte sequence), then the count of outputs and each output (8-byte two's-complement value, prefixed script), then, if $\phi = 1$, for each input a CompactSize count of witness items followed by each item length-prefixed, then the 4-byte lock time.

**Unfolding the parser.** $\texttt{readTx}\;aw$ reads the 4-byte version (unsigned), then a range-checked input list $\texttt{vin}_0$. If $\texttt{vin}_0$ is empty and $aw$ is true, it consumes one byte $fl$: if $fl \ne 0$ it re-reads an input list and reads an output list; if $fl = 0$ it sets the output list to $[\,]$ *without reading one*. Otherwise it reads the output list directly with flags $0$. Then, if the flags value is odd and $aw$ is true, it reads one witness stack per input, attaches them in order, and fails unless at least one stack is non-empty, decrementing the flags. Then it fails if the flags are still non-zero, and finally reads the 4-byte lock time.

**How the cases play out.** (i) $aw = \mathrm{false}$: $\phi = 0$, no marker; the parser never enters the flag branch; all fields are recovered and every parsed input has witness $[\,]$, which is why the conclusion names $\texttt{stripWitness}\;tx$ — this is an equality even if $tx$ had witnesses. (ii) $aw = \mathrm{true}$ and $\texttt{hasWitness}(tx)$: $\phi = 1$; the parser reads the input count $0$ from the marker, consumes $fl = 1$, re-reads inputs and outputs, reads $|\texttt{vin}|$ witness stacks, the non-empty-witness test passes, flags become $0$, lock time is read; the result is $tx$ with witnesses attached, i.e. $tx$. (iii) $aw = \mathrm{true}$, no witness: $\phi = 0$, the encoding is the legacy one; by $hv$ the input list is non-empty, so the parser takes the direct branch; result $tx$. The hypothesis $hv$ excludes exactly the case $aw = \mathrm{true}$, $\texttt{vin} = [\,]$, where the serialization begins with an input count of $0$ and the parser would read the *output count byte* as the flags byte (for $\ge 1$ outputs it would then try to re-parse inputs from output bytes; for $0$ outputs it would consume the count and still succeed with empty outputs); the theorem makes no claim there. The $\texttt{wf}$ bounds ensure that the truncating encoders and the range-checked, canonical readers recover every value; the signed range on values ensures the two's-complement decode is exact; the 32-byte hash lengths ensure the raw hash bytes are cut at the right place.

**What is not said.** Nothing about $aw = \mathrm{true}$ with no inputs. Nothing about parsing a witness serialization in non-witness mode or vice versa. No converse (parsed transactions need not be well-formed, and nothing says a successful parse came from $\texttt{serTx}$). Nothing about $\texttt{wf}$ of the result, about $\texttt{txid}$, or about lengths. It is the one-directional parse-after-serialize statement, per mode, under $\texttt{wf}$ and $hv$.
