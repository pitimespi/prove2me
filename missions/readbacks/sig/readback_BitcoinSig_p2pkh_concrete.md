# Read-back: `BitcoinSig.p2pkh_concrete`

**Binders and hypothesis.** Universally quantified over: a signature-layer flag record $f$ (Booleans `dersig`, `lowS`, `strictenc`, `witnessPubkeyType`); an interpreter flag record $fl$ (Booleans `cltv`, `csv`, `nulldummy`); a transaction $tx$; a natural number $nIn$; an integer $amount$; a signature version $v \in \{\text{base}, \text{witnessV0}\}$; and three byte strings $sig$, $pk$, $h$. Three hypotheses, each bounding a length by `MAX_SCRIPT_ELEMENT_SIZE` $= 520$:
- $hsig$: $|sig| \leq 520$;
- $hpk$: $|pk| \leq 520$;
- $hh$: $|h| \leq 520$.
Nothing else is assumed: $nIn$ may be out of range, $amount$ may be negative, $h$ need not have length 20, $v$ may be `witnessV0` even though the interpreter being run is the legacy one.

**Conclusion.** Let $O$ denote the oracle `legacyOracle` $f\,tx\,nIn\,amount\,v$ (`p2pkhBytes` $h$): the record whose hash functions are the serialization file's RIPEMD-160, SHA-1, SHA-256, Hash160 (RIPEMD-160 of SHA-256) and Hash256 (double SHA-256), whose `checkSig` $s\,k$ is `checkSigPreTapscript` $f\,tx\,nIn\,amount\,v$ (`p2pkhBytes` $h$) $s\,k$, and whose lock-time and sequence checks are `checkLockTime` $tx\,nIn$ and `checkSequence` $tx\,nIn$. Then
$$\text{verifyScriptPlain}\ fl\ O\ [\text{push}\ sig,\ \text{push}\ pk]\ (\text{p2pkhScript}\ h) = \text{true}$$
if and only if
$$\text{hash160}\ pk = h \quad\land\quad \text{checkSigPreTapscript}\ f\ tx\ nIn\ amount\ v\ (\text{p2pkhBytes}\ h)\ sig\ pk = \text{some true}.$$

**Unfolding the left side.** `verifyScriptPlain` $fl\,O\,ss\,spk$ evaluates the script $ss$ on the empty stack; if that fails ("none") the result is false; otherwise it evaluates $spk$ on the resulting stack; if that fails or leaves an empty stack the result is false; otherwise the result is `castToBool` of the top element (some byte is non-zero, except that a lone `0x80` after zeros counts as false). Evaluation starts from the state (main stack $[\,]$, alt stack $[\,]$, condition stack $[\,]$, op count $0$) and processes instructions in order; at the end the condition stack must be empty (it is, since no `OP_IF` occurs). Stacks are written top-first.

*Script 1*: `push` $sig$ — fails if $|sig| > 520$ (excluded by $hsig$), else pushes; stack $[sig]$. `push` $pk$ — likewise; stack $[pk, sig]$. The 1000-element stack limit is never approached.

*Script 2*: `p2pkhScript` $h$ is $[\text{op}\ \texttt{0x76},\ \text{op}\ \texttt{0xa9},\ \text{push}\ h,\ \text{op}\ \texttt{0x88},\ \text{op}\ \texttt{0xac}]$ (`OP_DUP`, `OP_HASH160`, the push, `OP_EQUALVERIFY`, `OP_CHECKSIG`). Each opcode byte exceeds `OP_16` and so is counted toward the 201-op limit (reaching 4, far below); none is disabled. `OP_DUP` duplicates the top: $[pk, pk, sig]$. `OP_HASH160` replaces the top by $O.\text{hash160}$ of it, i.e. `BitcoinSer.hash160` $pk$: $[\text{hash160}\ pk, pk, sig]$. `push` $h$ — fails if $|h| > 520$ (excluded by $hh$): $[h, \text{hash160}\ pk, pk, sig]$. `OP_EQUALVERIFY` pops two elements $a = h$, $b = \text{hash160}\ pk$ and succeeds (removing both) exactly when $b = a$ as byte strings, failing the whole script otherwise: $[pk, sig]$. `OP_CHECKSIG` pops $pubkey = pk$ and $sig$ and calls $O.\text{checkSig}\ sig\ pk$ = `checkSigPreTapscript` $f\,tx\,nIn\,amount\,v$ (`p2pkhBytes` $h$) $sig\,pk$: "none" fails the script; "some $ok$" pushes $[1]$ if $ok$ is true, or $[\,]$ if false. Final stack: $[[1]]$ or $[[\,]]$; `castToBool` gives true exactly for $[1]$. So the left side is true precisely when the equality check passed and the oracle returned "some true".

**Unfolding the right side's second conjunct.** `checkSigPreTapscript` with script code `p2pkhBytes` $h$ $= [\texttt{0x76}, \texttt{0xa9}] \,\|\, \text{pushBytes}\ h \,\|\, [\texttt{0x88}, \texttt{0xac}]$: if $v$ = `base` the script code first has every raw-byte occurrence of `pushBytes` $sig$ at instruction boundaries deleted (`findAndDelete`); if $v$ = `witnessV0` it is used unchanged. The result is "none" if `checkSignatureEncoding` $f\,sig$ or `checkPubKeyEncoding` $f\,v\,pk$ fails, else "some" of `checkECDSASignature` $tx\,nIn\,amount\,v\,sig\,pk\,sc$: false unless `pubkeyValid` $pk$ and $sig$ non-empty; otherwise, with $ht$ the last byte of $sig$ and $sig'$ the rest, the signature hash is `sigHashLegacy` $sc\,tx\,nIn\,ht$ (for `base`) or `sigHashWitnessV0` $sc\,tx\,nIn\,ht\,amount$ (for `witnessV0`, with "false" if $amount < 0$), and the verdict is `pubkeyVerify` $pk\,sighash\,sig'$.

**What is not said.** The statement does not say anything if any of the three lengths exceeds 520 (then the left side is false by a push failure while the right side may still hold; the hypotheses are what make the backward direction true). It does not say the interpreter flags $fl$ matter — they are never consulted on this script path (no CLTV, CSV or multisig), and the statement quantifies over them without using them. It does not restrict $v$ to `base`: for `witnessV0` the oracle still runs the legacy interpreter but hashes with the BIP143 algorithm, and the statement covers that combination too. It does not say $|h| = 20$. It does not say that `p2pkhBytes` $h$ is the byte serialization of `p2pkhScript` $h$ (that is a separate statement), nor that the script code passed to the oracle "is" the executed script in any sense beyond the way $O$ was built. It does not distinguish the script-error outcome "none" of the signature check from "some false": both make the left side false and the right side false. It does not say anything about `OP_CODESEPARATOR`, about the `findAndDelete` step altering `p2pkhBytes` $h$ (it can, if `pushBytes` $sig$ happens to occur in it), or about the cryptographic meaning of the verdict.
