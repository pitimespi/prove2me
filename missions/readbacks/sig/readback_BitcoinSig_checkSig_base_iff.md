# Read-back: `BitcoinSig.checkSig_base_iff`

**Binders and hypothesis.** The statement is universally quantified over: a flag record $f$ (four Booleans: `dersig`, `lowS`, `strictenc`, `witnessPubkeyType`); a transaction $tx$ (fields: natural-number `version`, list of inputs `vin`, list of outputs `vout`, natural-number `nLockTime`); a natural number $nIn$ (an input index, not required to be in range); an integer $amount$; and three byte strings $scriptCode$, $sig$, $pk$. There are no hypotheses: the statement is an unconditional biconditional.

**Conclusion.** The following two statements are equivalent.

*Left side.* The pre-tapscript signature check in `base` mode, namely `checkSigPreTapscript` $f\,tx\,nIn\,amount\,\text{base}\,scriptCode\,sig\,pk$, returns the value "some true". Unfolding that definition: let $sc$ be the first component of `findAndDelete` $scriptCode$ (`pushBytes` $sig$), i.e. $scriptCode$ with every raw-byte occurrence of the canonical push encoding of $sig$ removed at instruction boundaries (the push encoding is the length byte followed by $sig$ when $|sig| < 76$, and the `0x4c`/`0x4d`/`0x4e` forms for longer data; for the empty signature it is the single byte `0x00`). The result is "none" if `checkSignatureEncoding` $f\,sig$ is false or `checkPubKeyEncoding` $f\,\text{base}\,pk$ is false; otherwise it is "some" of `checkECDSASignature` $tx\,nIn\,amount\,\text{base}\,sig\,pk\,sc$, which is: false if `pubkeyValid` $pk$ fails or $sig$ is empty; otherwise, writing $sig = sig' \,\|\, [ht]$ with $ht$ the last byte, the Boolean `pubkeyVerify` $pk$ (`sigHashLegacy` $sc\,tx\,nIn\,ht$) $sig'$. In `base` mode the amount is never consulted.

*Right side.* The conjunction of four things:
1. `checkSignatureEncoding` $f\,sig$ = true — which holds vacuously if $sig$ is empty, and otherwise requires: strict DER structure (`isValidSignatureEncoding`) whenever any of $f$.dersig, $f$.lowS, $f$.strictenc is set; additionally low-$S$ of the signature without its final byte (`isLowDERSignature`) when $f$.lowS is set; additionally that the last byte masked with `0x7f` lies in $\{1,2,3\}$ when $f$.strictenc is set;
2. `checkPubKeyEncoding` $f\,\text{base}\,pk$ = true — i.e. if $f$.strictenc then $pk$ is 65 bytes starting with `0x04` or 33 bytes starting with `0x02`/`0x03`; the `witnessPubkeyType` flag has no effect in `base` mode;
3. `pubkeyValid` $pk$ = true — $pk$ is non-empty and its length equals the length its first byte announces (33 for `0x02`/`0x03`, 65 for `0x04`/`0x06`/`0x07`, otherwise an impossible 0);
4. there exist a byte string $sig'$ and a byte $ht$ with $sig = sig' \,\|\, [ht]$ and
$$\text{pubkeyVerify}\ pk\ \big(\text{sigHashLegacy}\ sc\ tx\ nIn\ ht\big)\ sig' = \text{true},$$
where $sc$ is exactly the `findAndDelete` result described above and $ht$ is used as the natural number in $[0,255]$ it denotes.

**Further unfolding of the verification.** `pubkeyVerify` $pk\,hash\,sig'$ is: false unless `pubkeyValid` $pk$; false unless `parsePubkey` $pk$ yields an affine point $Q$ (compressed keys are lifted from the abscissa with the announced parity; uncompressed/hybrid keys must have both coordinates below $p$, satisfy $y^2 \equiv x^3 + 7$, and for hybrid tags the announced parity); false unless the lax DER parser accepts $sig'$ with some pair $(r,s)$ (overflowing or over-long integers give $(0,0)$ rather than rejection); otherwise the raw ECDSA check with message $e = $ (big-endian value of $hash$) $\bmod n$, with $r$, and with $s$ replaced by $n - s$ whenever $s > \lfloor n/2 \rfloor$: false if $r$ or $s$ is $0$ or $\geq n$, else $R = (e s^{-1} \bmod n)\,G + (r s^{-1} \bmod n)\,Q$ must be finite with $R_x \bmod n = r$. `sigHashLegacy` $sc\,tx\,nIn\,ht$ is the constant `uint256One` (byte 1 followed by 31 zero bytes) if $ht \mathbin{\&} 31 = 3$ and $|tx.\text{vout}| \leq nIn$, and otherwise the double SHA-256 of the legacy signature serialization of $tx$ with script code $sc$ (with `OP_CODESEPARATOR` instructions removed) at input $nIn$ under hash type $ht$, followed by the 4-byte little-endian $ht$.

**What is not said.** The statement does not say anything about `witnessV0` mode. It does not say that $amount$ matters (it is bound but inert). It does not assert that the existential decomposition $sig = sig' \| [ht]$ is unique (though it is, since $ht$ is the last byte). It does not say what happens when the left side is "none" versus "some false": both are lumped into "not some true", so the right side being false does not distinguish an encoding failure from a failed verification. It does not say that the `findAndDelete` step leaves $scriptCode$ unchanged, nor that any of the four conjuncts is independent of the others (e.g. conjunct 3 is already implied by conjunct 4's `pubkeyVerify`). It does not relate the result to any notion of a "correct" signature; it is a restatement of the checker's control flow as a conjunction.
