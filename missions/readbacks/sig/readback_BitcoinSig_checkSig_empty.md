# Read-back: `BitcoinSig.checkSig_empty`

**Binders and hypothesis.** Universally quantified: a flag record $f$ (Booleans `dersig`, `lowS`, `strictenc`, `witnessPubkeyType`); a transaction $tx$; a natural number $nIn$; an integer $amount$; a signature version $v \in \{\text{base}, \text{witnessV0}\}$; byte strings $scriptCode$ and $pk$. One hypothesis $hpk$: `checkPubKeyEncoding` $f\,v\,pk$ = true. Unfolded: it is *not* the case that ($f$.strictenc is set and $pk$ fails `isCompressedOrUncompressedPubKey`, i.e. $pk$ is not [65 bytes starting `0x04`] and not [33 bytes starting `0x02` or `0x03`]), and it is *not* the case that ($f$.witnessPubkeyType is set, $v$ = `witnessV0`, and $pk$ is not [33 bytes starting `0x02`/`0x03`]). In particular $hpk$ holds for every $pk$ (including the empty string) when $f$.strictenc is false and either $f$.witnessPubkeyType is false or $v$ = `base`.

**Conclusion.**
$$\text{checkSigPreTapscript}\ f\ tx\ nIn\ amount\ v\ scriptCode\ [\,]\ pk = \text{some false},$$
i.e. the pre-tapscript check with the **empty** signature returns the verdict "false" (and not a script error "none", and not "true").

**Unfolding.** The script code used is: for `base`, the first component of `findAndDelete` $scriptCode$ (`pushBytes` $[\,]$) — note `pushBytes` $[\,]$ is the single byte `0x00`, so every `0x00` byte at an instruction boundary of $scriptCode$ is removed; for `witnessV0`, $scriptCode$ itself. `checkSignatureEncoding` $f\,[\,]$ is true unconditionally (the empty signature is exempt from every encoding check, whatever the flags). With $hpk$, neither "none" branch fires, so the result is "some" of `checkECDSASignature` $tx\,nIn\,amount\,v\,[\,]\,pk\,sc$. That function returns false if `pubkeyValid` $pk$ is false; otherwise it takes the last byte of the signature, and since the signature is empty there is none, so it returns false. In both cases the Boolean is false, giving "some false". The transaction, index, amount, version and script code are never used beyond this.

**What is not said.** The statement does not say anything about non-empty signatures. It does not say what happens when $hpk$ fails (then the result is "none"). It does not assert that the empty signature is *rejected as a script error* — it asserts precisely that it is *accepted as a well-formed check that evaluates to false*. It does not say anything about the public key beyond the encoding hypothesis; $pk$ may be garbage (e.g. empty, if the flags allow) and the result is still "some false". It does not mention that the `findAndDelete` step alters $scriptCode$ by deleting `OP_0` bytes, since the altered script code is never hashed in this case. It does not say anything about `witnessV0` amounts (the negative-amount rejection is never reached because the empty-signature check comes first).
