## Verdict

No defect. Every reader returns `none` exactly where Core throws and the same value where Core
returns, every writer emits the same bytes, and the weights are the same formula over the same
lengths. In particular: the CompactSize canonical thresholds (253, 0x10000, 0x100000000) and the
inclusive `MAX_SIZE = 0x02000000` bound; the flag-byte path of `UnserializeTransaction` including
its two odd corners (an empty `vin` followed by a zero flag leaves `vout` empty *without reading
it*; a `TX_NO_WITNESS` read of a witness serialization "succeeds" with a garbage transaction);
"Superfluous witness record" when the flag is set but every stack is empty; "Unknown transaction
optional data" for any flag other than 1 after the witness bit is consumed; serialization writes
the `00 01` marker only when some input has a non-empty stack (so a transaction whose stacks are
all empty serializes without it, and has `wtxid = txid`); `uint32_t version` read unsigned,
`int32_t nVersion` of the header read signed, `CAmount` as two's-complement int64. The blind
read-back (`scratchpad/audit10/readback_Def_BitcoinSer.md`) describes exactly this behaviour,
including the "vout is set to `[]` without being read" corner, which is what Core does. The
read-back's remark that `Block.wf` demands a non-empty `vin` concerns a hypothesis of the
round-trip theorems only (`Theorems/Thm_BitcoinSer_*`); no consensus predicate uses any `wf`.

Vectors: `tests/SerEdgeVectors.lean` (189 `#eval` lines, all `true`), generated by
`tests/reference/ser_reference.py`, an independent Python transcription of `serialize.h`,
`transaction.h` and `block.h`. One line was initially `false` because the *reference emitter* (not
the parser) hard-coded the trailing-byte remainder for the cross-mode case; the parsed fields the
Lean returned were exactly Core's parse, and the emitter was corrected to print the real remainder.

## `WriteCompactSize` / `ReadCompactSize` — `writeCompactSize` / `readCompactSize`

Core: `< 253` one byte; `≤ 0xffff` `fd` + LE16; `≤ 0xffffffff` `fe` + LE32; else `ff` + LE64.
Reading: `fd` with value `< 253`, `fe` with value `< 0x10000`, `ff` with value `< 0x100000000`
throw "non-canonical"; then `range_check && nSizeRet > MAX_SIZE` throws; short reads throw from
`ser_readdataN`. The default `range_check = true` is what every vector/prevector reader uses.

The Lean: the same four write cases with the same inclusive bounds; `readCompactSize rangeCheck`
returns `none` on `[]`, on each short `readLE`, on the three strict canonical tests, and on
`rangeCheck && MAX_SIZE < v`. `MAX_SIZE` itself is accepted with the check (`fe 00 00 00 02`),
`MAX_SIZE + 1` is rejected only with it; `ff 00 00 00 00 01 00 00 00` (2^32) is accepted without
the check and rejected with it. Identical.

## `Unserialize(vector<T>)`, `Unserialize(prevector)` — `readList`, `readBytes`

Core: `VectorFormatter::Unser` clears the vector, `ReadCompactSize(s)` (range-checked), then reads
exactly that many elements one by one (the 5 MiB batching of `reserve` is allocation only). The
byte-vector and prevector (`CScript`) readers do `ReadCompactSize(is)` then `is.read` of that many
bytes, throwing when the stream is short. A witness stack is `vector<vector<unsigned char>>`, so
its count and every element length are range-checked. `uint256` is 32 raw bytes.

The Lean: `readList f` = `readCompactSize true` then `readN f n`; `readBytes` = `readCompactSize
true` then `none` if fewer than `n` bytes remain; `readWitnesses` = `readN (readList readBytes)`;
`readHash` = 32 raw bytes. Identical.

## `UnserializeTransaction` — `readTx`

Core, in order: `version` (`uint32_t`, LE); `vin` as a vector; if `vin.size() == 0 &&
fAllowWitness`: one `flags` byte; if `flags != 0` read `vin` and `vout` again (the vector reader
clears first), otherwise `vout` stays *empty and is not read*; else (non-empty `vin`, or witness
disallowed) read `vout`. Then if `(flags & 1) && fAllowWitness`: `flags ^= 1`, read one stack per
input, throw "Superfluous witness record" unless some stack is non-empty. Then any remaining
`flags` bit throws "Unknown transaction optional data". Then `nLockTime`.

The Lean `readTx allowWitness`: `readLE 4` for `version` (unsigned `Nat`); `readList readTxIn`;
`step2`: if `vin0.isEmpty && allowWitness`, the next byte is `fl` (`none` if absent), `fl ≠ 0` →
re-read `vin` and `vout`, `fl = 0` → `(0, [], [], s)` with nothing read; otherwise read `vout`.
`step3`: if `flags % 2 = 1 && allowWitness`, `readWitnesses vin.length`, attach, require
`hasWitness`, carry `flags - 1` (= `flags ^ 1` for odd `flags`). Then `flags ≠ 0 → none`, then
`readLE 4` for `nLockTime`. The same control flow, test by test. Consequences checked by vector:
`01000000 00 00 efbeadde` parses as a 0-in/0-out transaction with lock time `0xdeadbeef` under
both parameters; `01000000 00 00 01 02 03 04 05` parses with `vout = []` and lock time
`0x04030201` leaving `[05]`; `01000000 00 01 00 00 00000000` is `none` (no stacks, so no witness);
the flag byte 2 (and `0x81`, and 3 with a real witness) is `none`; a `TX_NO_WITNESS` read of a
`TX_WITH_WITNESS` serialization of a 2-input transaction yields the garbage transaction Core
yields (`vin = []`, one output whose value is the first 8 bytes of the first input, lock time
from the hash bytes) with the long remainder.

## `SerializeTransaction` — `serTx`

Core: `version`; `flags = 1` iff `fAllowWitness && HasWitness()` where `HasWitness` is "some
input's `scriptWitness.stack` is non-empty" (`script.h:586`); if `flags`, an empty `vin` (`00`) and
the flag byte; `vin`; `vout`; if `flags & 1`, every input's stack (including empty ones, as `00`);
`nLockTime`. The Lean `serTx allowWitness` is the same six pieces in the same order with
`flags := if allowWitness && tx.hasWitness then 1 else 0`. A transaction whose stacks are all
empty is serialized without the marker in both modes (`serTx true = serTx false`, verified); a
stack `[[]]` (one empty element) counts as a witness (`01 00`). `Tx.stripWitness` is what a
`TX_NO_WITNESS` read of the stripped serialization yields, and what a `TX_NO_WITNESS` read of the
witness serialization does *not* yield (vector).

## `CBlockHeader`, `CBlock` — `serHeader`/`readHeader`, `serBlock`/`readBlock`

Core: `int32_t nVersion` (LE, two's complement), two `uint256`, three `uint32_t`; a block is the
header then `vtx` as a vector of `CTransactionRef`, each serialized with the stream's parameters.
The Lean: `serInt32`/`readInt32` for the version (`0xffffffff` ↔ `-1`, `0x80000000` ↔ `-2^31`,
`0x7fffffff` ↔ `2^31-1`), raw hashes, `ser32`/`readLE 4` for the rest; `serBlock allowWitness` =
`serHeader ++ serList (serTx allowWitness)`. The genesis header serializes to the known 80 bytes
and hashes to `genesisHash`. `(serBlock false b).length` is `GetSerializeSize(TX_NO_WITNESS(b))`
= `80 + CompactSize + Σ stripped sizes` (vector on a four-transaction block with two witness
transactions). Identical.

## `ComputeHash`, `ComputeWitnessHash`, `HasWitness` — `txid`, `wtxid`, `Tx.hasWitness`

Core: `hash = SHA256d(TX_NO_WITNESS(tx))`; `witness hash = hash` if `!HasWitness()`, else
`SHA256d(TX_WITH_WITNESS(tx))`. The Lean: `txid = hash256 (serTx false tx)`, `wtxid = if
hasWitness then hash256 (serTx true tx) else txid`. Identical (the branch is also immaterial
since `serTx true = serTx false` without a witness).

## `GetTransactionWeight`, `GetBlockWeight` — `txWeight`, `blockWeight`

Core: `GetSerializeSize(TX_NO_WITNESS(x)) * (WITNESS_SCALE_FACTOR - 1) +
GetSerializeSize(TX_WITH_WITNESS(x))` with `WITNESS_SCALE_FACTOR = 4`; the block variant is used
by `ContextualCheckBlock` against `MAX_BLOCK_WEIGHT = 4,000,000`. The Lean: `(serTx false
tx).length * (4 - 1) + (serTx true tx).length`, and the same with `serBlock`; `Def_BitcoinBlockV2`
uses `blockWeight b ≤ MAX_BLOCK_WEIGHT`. The vectors check the formula against the reference's
sizes, `blockWeight = Σ txWeight + 4·(80 + CompactSize)`, and `txWeight = 4·|tx|` for a transaction
without a witness. `int32_t`/`int64_t` cannot overflow on inputs that pass the limit; the Lean
uses `Nat`.

## Checks from the guide

- **Order of tests.** `readTx` performs Core's reads and tests in Core's order (version, vin,
  flag, vin/vout, vout, stacks, superfluous, unknown flag, lock time), so the consumed byte count
  and the remainder agree, not only the verdict; `readCompactSize` tests canonicality before the
  range check, as Core.
- **Constants.** 253, 0x10000, 0x100000000, `MAX_SIZE = 0x02000000` (inclusive), marker `00 01`,
  `WITNESS_SCALE_FACTOR = 4`, header size 80: all match.
- **Integer semantics.** `version`, `nLockTime`, `nSequence`, `n` are `uint32_t` and `Nat`;
  `nValue` is `int64_t` and `Int` with two's-complement encode/decode checked at `-1`, `-2^63`,
  `2^63-1`; `nVersion` is `int32_t` checked at `-1`, `-2^31`, `2^31-1`; the writers truncate
  modulo `2^(8k)` as `ser_writedataN` casts do (only reachable outside `wf`). `flags - 1` on an
  odd `Nat` equals `flags ^ 1`.
- **Defaults.** No `headD`/`getD`; every reader is total through `Option`, with `none` exactly on
  Core's throws. `attachWitness` is only applied to lists of equal length (`readWitnesses
  vin.length`).
- **Policy vs consensus.** Serialization carries no policy; `MAX_SIZE` is enforced on every
  consensus deserialization in Core; `MAX_VECTOR_ALLOCATE` batching and the `SizeComputer` are
  performance only. `Block.wf`/`Tx.wf` are theorem hypotheses, not rules.
