## Verdict

No defect. Every test, its order and every constant agree with Core; the read-back
(`readback_Def_BitcoinBlockV2.md`, `Transactions` and `CheckTxInputs` sections) describes the
Lean as Core reads. Vectors: `tests/TxCheckVectors.lean` (35 lines, all `true`), generated by

## `CheckTransaction` — `checkTransaction`

Core, in order: `vin` empty; `vout` empty; `GetSerializeSize(TX_NO_WITNESS(tx)) * 4 > 4,000,000`;
for each output `nValue < 0`, `nValue > MAX_MONEY`, running total `MoneyRange`; duplicate prevouts
(a `std::set<COutPoint>` insert failing); coinbase: `vin[0].scriptSig.size()` in `[2, 100]`;
otherwise no input with `prevout.IsNull()`. `IsCoinBase` is `vin.size() == 1 && vin[0].prevout.IsNull()`,
`IsNull` is `hash.IsNull() && n == 0xffffffff`.

The Lean: `!vin.isEmpty && !vout.isEmpty && (serTx false tx).length * 4 ≤ 4,000,000 && (outputsLoop
vout 0).isSome && (vin.map prevout).Nodup && (if isCoinBase then 2 ≤ |scriptSig| ∧ |scriptSig| ≤ 100
else vin.all (!outPointNull))`, with `outputsLoop` the same three tests per output in the same
order, `isCoinBase` matching exactly one input with a null prevout, and `outPointNull` the 32 zero
bytes and `n = 0xffffffff`. `Nodup` on the prevout list is the set-insert test. Identical. The
`headD` default for the coinbase input is unreachable (`isCoinBase` forces one input).

Vectors: every rejection and both sides of each boundary (`MAX_MONEY`, the sum, 2 and 100 bytes), a
null hash with index 0 and a non-null hash with index `0xffffffff` (neither null, both accepted), a
"coinbase" with two inputs (not a coinbase, rejected for the null prevout), and a transaction whose
stripped size is exactly 1,000,000 bytes (accepted) against one byte more (rejected).

## `CheckTxInputs` — `checkTxInputs`

Core: `HaveInputs` (every prevout present; a coinbase passes vacuously, but `ConnectBlock` never
calls `CheckTxInputs` for the coinbase); for each input: `coin.IsCoinBase() && nSpendHeight −
coin.nHeight < COINBASE_MATURITY (100)` → premature; `nValueIn += coin.out.nValue`; `!MoneyRange(coin
value) || !MoneyRange(nValueIn)` → out of range; then `nValueIn < GetValueOut()` → `in-belowout`;
`txfee = nValueIn − value_out`, `!MoneyRange(txfee)` → unreachable by the comment's argument.

The Lean: `vin.all haveCoin`, then `inputsLoop` (lookup, the maturity test with a truncated `Nat`
difference, the two range tests after the addition), then `valueIn < valueOut → none`, `!moneyRange
(valueIn − valueOut) → none`, else `some fee`. Identical. The truncated subtraction gives `0 < 100`
when a coin's height exceeds the spend height, where Core's negative difference is also `< 100`:
same verdict (and unreachable on a chain). The Lean has no coinbase bypass in `haveCoin`; it is
not needed because `connectLoop` skips `checkTxInputs` for the coinbase, as Core does, and the
vector shows the function itself returns `none` for a coinbase, which no caller observes.

Vectors: fee of one and two coins, value out above value in, a missing input, the maturity boundary
at 99 and 100 blocks and below the coin's height, no maturity for non-coinbase coins, a coin of
exactly `MAX_MONEY`, a coin above it, a negative coin, a running total above `MAX_MONEY`.

## Checks from the guide

- **Order of tests.** The same; verdict-only semantics.
- **Constants.** `MAX_MONEY = 2.1·10^15`, `COINBASE_MATURITY = 100`, the `[2, 100]` scriptSig range,
  `4,000,000`, `0xffffffff`.
- **Integer semantics.** Amounts are `Int` (Core `CAmount` = `int64_t`, never overflowing under the
  running `MoneyRange` tests); the one `Nat` subtraction is verdict-equivalent as shown.
- **Defaults.** `headD` unreachable; `accessCoin`'s dummy coin is not used by `checkTxInputs`
  (`inputsLoop` matches on `getCoin`).
- **Policy vs consensus.** `IsStandardTx`, dust, the fee-rate rules are absent, correctly; the
  `TX_MISSING_INPUTS`/`TX_PREMATURE_SPEND` result classes are mempool bookkeeping and do not change
  the block verdict.
