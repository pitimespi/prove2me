## Verdict

No defect. The undo-count test, the reverse order of transactions and of inputs, the per-output
exact-match test lowering `fClean`, the two `IsBIP30Unspendable` blocks (hashes checked in
serialized order against Core's display strings), the `DISCONNECT_FAILED` cases and the
`possible_overwrite` semantics of `AddCoin` agree with Core. One remark, verdict-irrelevant:

**R2 (`applyTxInUndo`, legacy metadata branch).** When an undo coin has height 0 (undo data from
versions before 0.14, which recorded height and coinbase flag only on the last spend of a
transaction's outputs), Core's `AccessByTxid` takes the metadata of the *lowest-indexed* unspent
output of the same txid; the Lean takes the *first entry in the association list* with that txid.
All unspent outputs of one txid carry the same height and flag in any ledger this model or Core
produces (a transaction's outputs are added together by `AddCoins`, and a duplicate coinbase
overwrites all of them together), so the two choices never differ in content; and the model never
produces height-0 undo data (limit L7). Recorded for completeness.

Vectors: `tests/UndoVectors.lean` (32 lines, all `true`), generated by
`tests/reference/txcheck_undo_reference.py` from a dictionary coin view written from the C++. One
of my first expectations was wrong: I reused undo data recorded at height 200 to disconnect a
ledger connected at height 91722, and expected a clean result; the restored in-block coin then
carries height 200 and the Lean correctly reports the mismatch as unclean. The vector now records
the undo at the matching height and keeps the mismatched case as a negative test.

## `DisconnectBlock` — `disconnectBlock`

Core: `vtxundo.size() + 1 != vtx.size()` → `FAILED`; `fEnforceBIP30 = !(height 91722 with hash
…dd08e ∨ height 91812 with hash …06f2f)`; for `i` from the last transaction down to 0:
`is_bip30_exception = IsCoinBase && !fEnforceBIP30`; for every output `o` in index order whose
`scriptPubKey` is not unspendable: `SpendCoin(out, &coin)`; if it was not present, or its `out`,
`nHeight` or coinbase flag differs from the block's, `fClean = false` unless excepted; then, for `i >
0` (by position, not by `IsCoinBase`): `vprevout.size() != vin.size()` → `FAILED`; for `j` from the
last input down to 0: `ApplyTxInUndo`; `FAILED` propagates; `UNCLEAN` lowers `fClean`.
`SetBestBlock` is bookkeeping.

The Lean: `undo.length + 1 ≠ vtx.length → none`; `exception := isBIP30Unspendable height hash`;
`disconnectTxs` over `(vtx.zip (none :: undo.map some)).reverse`, so the first transaction by
position has no undo and the others have theirs; `disconnectTx`: `spendOutputs` with `cb &&
exception` (the unspendable skip, `getCoin` for presence, the three equality tests, `spendCoin`
whether or not it matched, `ok || exception`), then for `some coins`: `coins.length ≠ vin.length →
none`, `restoreInputs (vin.zip coins)`, which recurses on the tail first so the last input is
restored first. The clean flags are conjoined across outputs, inputs and transactions. Identical.

## `ApplyTxInUndo` — `applyTxInUndo`

Core: `fClean = !HaveCoin(out)`; `undo.nHeight == 0` → metadata from `AccessByTxid` (an unspent
output of the same txid) or `FAILED`; `AddCoin(out, undo, possible_overwrite = !fClean)`, which
stores nothing for an unspendable script and otherwise replaces the entry; return `OK` or
`UNCLEAN`. The Lean: `clean := !haveCoin u out`; the height-0 branch via `find?` (R2 above) or
`none`; `addCoin u out c` (the unspendable test, then replace); `some (ledger, clean)`. Identical
in every reachable case.

## Vectors

A ledger with two plain coins and one coinbase coin; a block of a coinbase (with an `OP_RETURN`
second output), a transaction spending both plain coins, and a transaction spending the first's
output in-block (with an `OP_RETURN` output). The undo the model records equals what `UpdateCoins`
moves out; `OP_RETURN` outputs are never stored; the round trip is clean and restores exactly the
three original coins; the undo-count and `vprevout`-size mismatches fail; an output already spent
elsewhere, a height mismatch, a coinbase-flag mismatch and a value mismatch are unclean but
succeed and still restore the ledger; restoring over an existing coin is unclean and overwrites;
a height-0 undo coin fails when restored before its sibling and succeeds (copying the sibling's
metadata) when restored after it, which pins the reverse input order; at height 91722 with the
right hash a missing coinbase output is excused while a missing non-coinbase output is not, the
hash goes with its height, and the other hash is not excused; the two exception hashes match
Core's display strings reversed.

## Checks from the guide

- **Order of tests.** Transactions and inputs in reverse, outputs forward; the same.
- **Constants.** The two heights and hashes; no others.
- **Integer semantics.** None beyond equality tests.
- **Defaults.** None: `spendCoin` on an absent key is a no-op in both.
- **Policy vs consensus.** `DisconnectBlock` is part of reorganization, which the model states as
  the `disconnect_connect` theorem (limit L3: one block at a time).
